# 前端开发规范

> 适用范围：`apps/web` 及后续复用 `packages/shared` 的前端应用。
> 本规范以仓库实际锁定依赖为准（见 `apps/web/package.json`）。若与《前端搭建步骤》的冻结版本表不一致，**以 `package.json` 实际安装版本为准**；升级依赖前必须先评估 peer 兼容性。
> 强制级别：🔴 红线（禁止 / 必须）｜🟡 约定（团队默认，lint 未硬性拦截）｜🟢 建议。

## 3. 目录结构约定

```
apps/web/src/
├─ app/                 # 应用入口与全局装配
│  ├─ main.tsx          # 仅负责挂载根组件 + 引入 global.css
│  ├─ router.tsx        # 集中式路由表（已豁免 react-refresh 规则）
│  ├─ AuthLayout.tsx    # 受保护布局（Outlet + 导航 + 退出登录）
│  ├─ guards/           # 路由守卫（RequireAuth 等）
│  └─ providers/        # 全局 Provider 装配（Query / AntdApp / ConfigProvider）
├─ pages/               # 页面级组件，一个页面一个目录
│  └─ Login/            #   index.tsx（页面）+ index.test.tsx（同名测试同目录）
├─ components/          # 可复用展示 / 业务组件（非页面）
├─ hooks/               # 自定义 hooks（useXxx）
├─ stores/              # zustand store，按域拆分（user.ts / app.ts ...）
├─ shared/api/          # 接口请求封装（基于 axios 实例）
├─ utils/               # 纯函数工具（无副作用、可单测）
├─ types/               # 跨模块共享类型
└─ styles/              # global.css（统一样式入口）+ variables.less（组件级 less 变量）
```

- 🟡 **页面只做组合**，业务逻辑下沉到 `components` / `hooks` / `stores`，禁止在页面文件写长业务函数。
- 🟡 `pages/<Name>/index.tsx` 是页面入口；同名测试 `index.test.tsx` 必须放同目录（便于维护与定位）。

## 4. 代码风格（ESLint + Prettier）

已启用的规则集（`apps/web/eslint.config.ts`）：
- `@eslint/js` recommended
- `typescript-eslint` recommended
- `react-hooks` recommended（含 `rules-of-hooks`、`exhaustive-deps`）
- `react-refresh/only-export-components`（warn，允许常量导出）
- `eslint-config-prettier`（最后加载，关闭与 Prettier 冲突的规则）

约定：
- 🟢 **Prettier 是格式化唯一来源**，ESLint 不与之打架（配置末尾已 `extends: prettier`）。不要手改 Prettier 已管的事项（引号、分号、缩进）。
- 🟡 文件只导出一个主组件；若需同时导出常量 / 工具，拆分文件（参考 `router.tsx` / `RequireAuth.tsx`，二者已在 `src/app/**` 豁免 `react-refresh/only-export-components`）。
- 🟡 命名：组件 `PascalCase`、hook `useXxx`、普通文件 `kebab-case`、常量 `UPPER_SNAKE_CASE`。
- 🟢 import 顺序建议：第三方库 → `@/` 内部别名 → 相对路径 → 样式 / 资源。（Prettier 不排序 import，可手动保持或后续引入 `import/order`。）

## 5. TypeScript 规范

- 🔴 **`strict` 开启，禁止 `any`**。无类型第三方用 `unknown` + 类型收窄，而非 `any`。
- 🔴 禁止用 `// @ts-ignore` / `@ts-expect-error` 逃避检查（除非极少数、且带理由注释）。
- 🟡 所有外部边界数据（API 响应、路由参数、环境变量）一律用 **zod schema** 定义，并在边界 `safeParse` 校验，不信任后端。
- 🟢 路径别名 `@` 指向 `src`（Vite + tsconfig 已配）。相对路径超过两级改用 `@`。
- 🟢 组件 Props 用 `interface` / `type` 显式声明，不写 `React.FC`（其默认 children 类型在 React 19 下行为变化）。

---

## 6. 组件规范

- 🔴 一律函数组件；Props 必须有显式类型。
- 🟡 **展示组件与容器组件分离**：数据获取放 `hooks` 或 TanStack Query，组件只负责渲染与交互。
- 🟡 antd 6 主题用 `ConfigProvider` 的 `theme.token`，不依赖 less 定制（antd 6 包内无 less 源，见 §11）。
- 🟢 列表 / 条件渲染优先用 antd 组件（`Table` / `Form` / `Modal`），不重复实现。

---

## 7. 路由与导航

- 🟡 路由表集中在 `app/router.tsx`（`createBrowserRouter`），不要在页面里散落路由。
- 🟡 受保护路由用 `RequireAuth` 包裹（基于 `localStorage` 的 `token` 字段拦截），布局用 `AuthLayout`（含 `<Outlet/>` + 导航 + 退出登录）。
- 🟢 页面级路由组件用 `React.lazy` + `Suspense` 懒加载，做路由级 code splitting。
- 🟢 退出登录 = 清 `token` + 跳 `/login`，统一复用 `RequireAuth` 导出的 `TOKEN_KEY` 常量。

---

## 8. 状态管理

- 🟡 **客户端全局状态用 zustand**，按域拆 store（`stores/user.ts`、`stores/app.ts`），避免单一大 store。
- 🟡 **服务端数据用 TanStack Query**（缓存、重试、失效），不进 zustand、不手动 `useState` 缓存接口数据。
- 🟡 表单局部状态用 `react-hook-form`；避免 `useState` 堆表单字段。
- 🔴 **prop drilling 禁止超过两层**，否则提 store 或 context。

---

## 9. 数据与 API

- 🔴 **统一走 axios 实例**（`shared/api/client.ts`）：封装 `baseURL`、请求拦截（注入 `token`）、响应拦截（错误归一、401 跳登录）。
- 🔴 禁止在组件里裸写 `fetch`（除非极简单次请求）。
- 🟡 响应类型用 zod 解析（`safeParse`），不手写与后端耦合的接口；解析失败按错误处理，不吞异常。
- 🟡 `token` 读取统一走 `RequireAuth` 导出的 `TOKEN_KEY`（即 `localStorage` 的 `token`），不要各处硬编码字符串。

---

## 10. 表单规范

- 🟡 表单统一 `react-hook-form` + `zodResolver`（`@hookform/resolvers/zod`）。
- 🟡 校验 schema 用 zod 定义，类型由 `z.infer` / `z.input` 推导，不手写重复 TS 接口。
- 🟢 校验文案中文、贴近业务（如「请输入邮箱」「密码至少 8 位」）。

---

## 11. 样式规范（重点，已踩坑）

- 🔴 **统一样式入口**：`main.tsx` 只引一个 `@/styles/global.css`，不要在别处再引 `antd/dist/reset.css`。
- 🔴 **Tailwind 指令只能写在 `.css` 里，绝不能写进 `.less`**。否则 Vite 先跑 less 编译器，会把 `@import "tailwindcss"` 当成磁盘文件路径报错。
- 🔴 **`global.css` 用 `@import "tailwindcss/utilities"`（仅 utilities 层）**，不要全量引入。全量含 preflight，会和 `antd/dist/reset.css` 双重 reset 冲突（antd 按钮样式丢失、标题字号被改）。
- 🟡 业务样式：优先 Tailwind 工具类；复杂 / 主题化用 `.less`，变量来自 `variables.less`（经 `vite.config` 的 `additionalData` 自动注入，组件 `.less` 无需手动 `@import`）。
- 🟡 antd 主题用 `ConfigProvider` 的 `theme.token`（`colorPrimary` / `borderRadius` 等），**不靠 less `modifyVars`**（antd 6 无 less 源）。
- 🟢 不写死颜色：主色等用 Tailwind `@theme` 或 antd token 对齐，保持两端一致。

## 12. 测试规范

- 🟡 框架 `vitest` + `@testing-library/react` + `jsdom`；配置在 `vite.config` 的 `test` 段 + `src/test-setup.ts`。
- 🟡 测试文件 `*.test.tsx` 与被测文件**同目录**；组件测试放 `pages/<Name>/index.test.tsx`。
- 🔴 **必须包裹所需 Provider**：Router 用 `MemoryRouter`，Query 用 `QueryClientProvider`，主题用 `ConfigProvider` / `AntdApp`。缺上下文的 `render(<Login/>)` 会直接失败。
- 🟢 `jsdom` 缺 `matchMedia`，antd 响应式断点需在 `test-setup.ts` 里 mock（已做，勿删）。
- 🟢 断言用 `@testing-library/jest-dom` 匹配器（`toBeInTheDocument` 等）；测用户可见行为，不测实现细节。

## 17. 环境变量与配置

- 🔴 **前端 env 禁止存真实密钥**：所有 `VITE_` 前缀变量会被原样打进构建产物，任何人打开浏览器 DevTools 都能拿到。真密钥只存在后端 / 网关。
- 🟡 **命名约定**：`VITE_<域>_<用途>`，按域分组——
  - `VITE_API_BASE_URL`（API 地址）、`VITE_API_TIMEOUT_MS`（超时）
  - `VITE_APP_TITLE`（应用名）、`VITE_APP_VERSION`（版本号）
  - 第三方只放「公开配置」：`VITE_SENTRY_DSN`、`VITE_GA_ID` 这类本就设计为公开的标识
- 🟡 **类型声明**：新增变量必须同步两处——`apps/web/.env.example`（写空值或示例值，入库）+ `vite-env.d.ts` 的 `ImportMetaEnv` 接口（否则 `import.meta.env.XXX` 是 `any`）：

```ts
// apps/web/src/vite-env.d.ts
/// <reference types="vite/client" />
interface ImportMetaEnv {
  readonly VITE_API_BASE_URL: string;
  readonly VITE_APP_TITLE: string;
}
interface Meta {
  readonly env: ImportMetaEnv;
}
```

- 🟢 多环境文件：`.env`（全环境默认）→ `.env.development` → `.env.production`，Vite 按 `MODE` 自动叠加；本地私有值放 `.env.local`（已被 .gitignore 的 `*.local` 覆盖，不入库）。
- 🟢 读取时禁止解构（`const { VITE_API_BASE_URL } = import.meta.env` 会丢响应性追踪，统一 `import.meta.env.VITE_API_BASE_URL` 或封装 `config.ts` 单点读取）。

## 18. 错误处理与页面四态

- 🔴 **列表 / 数据页必须实现四态**：
  | 状态 | 实现方式 |
  |---|---|
  | loading | antd `Skeleton` / `Spin`（列表用 Skeleton，操作用 Spin） |
  | empty | antd `Empty`（或 Table 自带 `locale.emptyText`） |
  | error | antd `Result` 带「重试」按钮（TanStack Query 场景直接调 `refetch`） |
  | success | 正常渲染 |

- 🟡 **请求错误统一归一**：axios 响应拦截器把后端错误归一为 `{ code, message, httpStatus }` 结构，UI 层只消费归一结果：
  - 401 → 清 token 跳登录（拦截器内处理，页面无需感知）
  - 403 → `Result status="403"` 页面级展示
  - 5xx / 网络错误 → `message.error` 全局提示（同一时刻只弹一条，做去重）
  - 业务码错误 → 由调用方决定是 `message` 还是表单字段错误
- 🟡 **禁止吞错**：`catch` 里什么都不做（空 catch / 只 `console.log`）视为 bug；至少要给用户可见反馈或上报。
- 🟡 **ErrorBoundary 使用位置**：路由级必须有（每个懒加载路由包一层，fallback 用 antd `Result`）；组件级按需（图表等易碎重组件）。React 19 中 class 组件仅允许用于 ErrorBoundary。
- 🟢 TanStack Query 天然管理 loading/error 状态（`isLoading` / `isError` / `refetch`），页面直接消费，不要自己 `try/catch` 再存 `useState`。

## 19. 安全规范

- 🔴 **禁止裸用 `dangerouslySetInnerHTML`**：富文本必须先经 `DOMPurify.sanitize()`（或服务端已消毒的可信来源，需注释说明依据）。
- 🟡 **token 存储现状与决策记录**：当前 token 存 `localStorage`（key: `token`）——存在 XSS 可窃取风险。**这是演示期有意的取舍**（无后端、快速验证路由守卫），接真实后端时评估迁移 `httpOnly cookie` 或至少配合 CSP 降险。此决策变更须在本文档更新。
- 🟡 **URL / 路由参数不可信**：`useSearchParams` / `useParams` 取到的值用于请求前必须 zod 校验（如分页 `page` 用 `z.coerce.number().int().min(1)` 收窄）。
- 🟡 **防 XSS 默认安全**：React 转义已覆盖常规场景，风险点只剩 `dangerouslySetInnerHTML`、`href="javascript:"` 类注入——后者在渲染外部链接时校验协议（只放行 `http(s)`）。
- 🟢 **依赖安全**：CI 可选启用 `pnpm audit --prod`（仅生产依赖，dev 依赖漏洞不阻塞）；新依赖引入前在 PR 里注明来源与必要性（规范 §14「不引入未使用依赖」）。

## 21. 日期时间处理

- 🔴 **禁止裸 `new Date()` / `Date.now()` 写业务逻辑**：时区解析、月份从 0 起、字符串解析浏览器差异全是坑。业务代码统一 dayjs（已装 `^1.11`）。
- 🟡 **与后端的时间传输格式写死为 ISO 8601 字符串**（`2026-10-29T10:00:00Z`），前端不做「时间戳秒/毫秒」猜测；展示层统一 `dayjs(value).format("YYYY-MM-DD HH:mm")`。
- 🟡 **antd DatePicker 配套**：antd 6 的 DatePicker 依赖 dayjs 插件（`customParseFormat` / `weekday` 等），统一在入口处 `dayjs.extend(...)` 一次，不要散落在组件里。
- 🟢 相对时间展示（「3 分钟前」）用 dayjs `relativeTime` 插件 + `zh-cn` locale；封装 `utils/datetime.ts`（`formatDateTime` / `formatRelative`）单点维护，禁止页面里散写 format 字符串。
- 🟢 持续时间 / 倒计时计算基于 dayjs `diff`，不用手写毫秒减法。

## 22. 注释与命名

- 🟡 **注释写「为什么」，不写「是什么」**：代码能自解释的不要注释；注释的正当场景是——业务背景（「财务要求负数显示红色」）、非常规写法的原因（「此处不用 useEffect 因为 xxx」）、临时方案与到期条件。
- 🟡 **导出函数 / hook 必须有 JSDoc**（`@param` / `@returns`），组件用 Props interface 自文档 + 一句话职责说明；非导出（内部实现）不强制。
- 🟡 **TODO 格式**：`// TODO(owner): 描述` 或 `// FIXME(owner): 描述`——无 owner 的 TODO 等于没有 TODO。
- 🟢 命名达意优先于注释补丁：需要注释才能看懂的变量名，先改名。
- 🟢 禁止「注释掉的大段死代码」进仓库——git 历史就是存档，要找回用 git。

## 23. 浏览器兼容目标

- 🟡 **支持矩阵（写死）**：Chrome / Edge ≥ 100、Safari ≥ 15、Firefox ≥ 100（覆盖近两年常青浏览器；国产套壳内核多为 Chromium 100+，顺带覆盖）。不支持 IE，任何 IE 兼容需求直接拒绝。
- 🟡 **构建目标对齐**：Vite `build.target` 保持默认（`baseline-widely-available` 级别），不手动调低到 es2015——需要 polyfill 的需求出现时再评估，而不是预防性引入 core-js。
- 🟢 新 API 使用检查：`?.`、`??`、`Array.at()`、`structuredClone` 等按 [caniuse](https://caniuse.com) 对照支持矩阵；CSS 用 Tailwind v4（v4 本身按支持矩阵编译）+ antd（自带兼容处理），自定义 CSS 避免仅新浏览器支持的属性（如 `:has()` 降级方案）。

## 24. 国际化与文案

- 🟡 **当前决策（轻量方案）**：不上 i18n 框架，但**文案必须集中**——页面级文案放 `pages/<Name>/constants.ts`，跨页面共享文案放 `src/constants/copy.ts`，禁止同一文案字符串在多处硬编码。这是为将来接 `react-intl` 留的迁移路径：届时只需把常量表替换为 `<FormattedMessage>` 映射。
- 🟡 **文案书写约定**：
  - 中文文案末尾不带标点（按钮、标签）；完整句子带标点
  - 按钮动宾结构（「新增资源」「导出账单」），不用「点击这里」
  - 空态文案给行动指引（「暂无资源，点击右上角新建」优于「暂无数据」）
  - 错误文案说人话（「网络不稳定，请稍后重试」优于「请求失败: ECONNABORTED」）
- 🟢 若产品确定出海再评估 i18next / react-intl；**这个决策变更的时机点**：出现第一个非中文用户需求时。

## 25. 性能监控与埋点

- 🟢 **Web Vitals 上报预留**：引入 `web-vitals` 库（LCP / CLS / INP），上报通道接后端日志接口或 Sentry；阈值参考——LCP < 2.5s、CLS < 0.1、INP < 200ms。
- 🟢 **埋点约定**：路由切换 PV 在 `router.tsx` 的全局监听处单点采集；按钮 / 功能点击埋点封装 `track(event, payload)` 工具函数，禁止散落各组件手写上报请求。
- 🟢 **排查工具约定**：React DevTools Profiler 看组件渲染次数与耗时（开「Highlight updates」定位多余渲染）；包体积用 `vite build` 产物报告（当前 antd chunk 605KB 已知，见 §14 拆分计划）；慢接口用 TanStack Query 的 `isFetching` + Devtools 观察。
- 🟢 监控指标不追求全量，先回答三个问题：首屏多快、哪最慢、用户卡在哪。
