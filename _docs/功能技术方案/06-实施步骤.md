## 第 1 步 契约（shared）

### 1.1 `audit-actions.ts` 加展示映射

现有文件只有 `AUDIT_ACTIONS` 与 `AuditAction`，追加四样：

| 名字 | 形状 | 用途 |
|---|---|---|
| `AUDIT_ACTION_LABELS` | `satisfies Record<AuditAction, string>` | 动作中文名，列表与筛选下拉同源 |
| `AUDIT_DOMAIN_LABELS` | `Record<string, string>` | `auth` / `member` / `resource` / `subscription` / `quota` / `tenant` 的中文名 |
| `AUDIT_OBJECT_TYPE_LABELS` | `Record<string, string>` | `member` / `resource` / `invite` 的中文名（对象列降级用） |
| `auditActionLabel(action: string)` | `string` | 未知动作原样返回，避免历史数据被渲染成 `undefined` |

**易错点**：`AUDIT_ACTION_LABELS` 的键**直接写字面量**（`'member.remove': '移除成员'`），不要写 `[AUDIT_ACTIONS.MEMBER_REMOVE]: ...` 计算属性——`as const` 对象里计算属性键会退化成 `string`，`satisfies Record<AuditAction, string>` 的穷尽性检查随之失效，将来漏加一条也不报错。

17 条文案（与 `AUDIT_ACTIONS` 一一对应）：

| 动作 | 文案 | 动作 | 文案 |
|---|---|---|---|
| `auth.login` | 登录 | `resource.create` | 创建资源 |
| `member.invite` | 邀请成员 | `resource.update` | 更新资源 |
| `member.role_change` | 修改成员角色 | `resource.delete` | 删除资源（移入回收站） |
| `member.disable` | 禁用成员 | `resource.restore` | 恢复资源 |
| `member.enable` | 启用成员 | `resource.purge` | 彻底删除资源 |
| `member.remove` | 移除成员 | `subscription.subscribe` | 订阅 |
| `member.transfer_owner` | 转让团队所有权 | `subscription.cancel` | 取消订阅 |
| `quota.adjust` | 调整配额 | `subscription.refund` | 退款 |
| `tenant.update` | 更新团队信息 | | |

### 1.2 新增 `contracts/audit.ts`

三个 schema + 三个 type，正文见方案 §7.4.2。两点补充：

- `action` 用 `z.enum(Object.values(AUDIT_ACTIONS), { error: '动作取值不合法' })`。已实测（zod 4.6.7）：类型会正确收窄成 17 项联合，故意写 `'member.nope'` 编译报错——若你发现它能赋值成功，说明写成了 `z.string()`。

## 第 2 步 装饰器与拦截器（唯一破坏性改动）

### 2.1 `decorators/audit.decorator.ts`

`AUDIT_KEY` 的值从 `AuditAction`（字符串）变成：

```ts
export interface AuditMeta {
  action: AuditAction;
  objectType?: AuditObjectType;   // 'member' | 'resource' | 'invite' | …
  objectIdParam?: string;         // 失败时从 req.params 取 id 的键名
}

export const Audit = (action: AuditAction, meta: Omit<AuditMeta, 'action'> = {}) =>
  SetMetadata(AUDIT_KEY, { action, ...meta } satisfies AuditMeta);
```

`AuditObjectType` 就定义在同文件（`'member' | 'resource' | 'invite'`），不要放进 shared 的 `audit-actions.ts`——它是拦截器的实现细节，前端用不到，放 shared 只会让契约包多一个没人消费的联合类型。

**`objectIdParam` 必须显式声明**，不做「params 里有 id 就取」的默认行为：`GET /invites/:token` 的 `:token` 是可直接兑换入团的明文令牌，默认提取等于把它写进 `audit_logs` 留存 180 天（方案 AC-26）。

### 2.2 `interceptors/audit.interceptor.ts`

三处改：

1. 读元数据：`getAllAndOverride<AuditMeta>(AUDIT_KEY, [ctx.getHandler()])`，`if (!meta) return next.handle()`，后面用 `meta.action`。
2. 成功分支提取（同步，不 await）：

```ts
const pickObject = (value: unknown, params: Record<string, string>, meta: AuditMeta) => {
  const body = (value ?? {}) as Record<string, unknown>;
  const str = (v: unknown) => (typeof v === 'string' && v ? v : undefined);
  return {
    objectId:
      str(body.id) ?? str(body.inviteId) ??
      (meta.objectIdParam ? str(params[meta.objectIdParam]) : undefined) ?? null,
    objectName: str(body.name) ?? str(body.nickname) ?? str(body.email) ?? null,
  };
};
```

3. 失败分支只从 params 取 id，`objectName` 为 `null`。

`record()` 的入参接口（`AuditRecord`）**已经有** `objectType` / `objectId` 字段，不用改；`detail` 上加 `objectName` 即可。

**易错点**

| 坑 | 说明 |
|---|---|
| `tap({ next })` 的 `value` 是否已解包 | Nest 正常会把 Promise 解开，`value` 就是 controller 的返回值。**实现前先验证**：临时在 `next` 里 `console.log(typeof value, value?.constructor?.name)`，跑一条 `POST /resources`，应看到 `object Object`。若看到 `Promise`，改用 `mergeMap(async (value) => { 提取; void record(); return value; })`——提取同步、写库不 await，契约不变 |
| 把提取写成 async | 一旦 `await` 了写库，主请求就要等一次 INSERT（Neon 跨区 5–20ms），违反「审计不阻塞主请求」 |
| `req.params` 为空 | 拦截器在路由匹配之后执行，`params` 有值；但 `@Body` 里的 id 拿不到——所以 `POST /invites` 只靠响应体 |
| spec 直接 `defineMetadata(AUDIT_KEY, 'member.remove')` | 形状变了，`meta.action` 会是 `undefined` → **静默不审计**。这是最危险的一种失败：不报错、不抛异常，只是记录消失 |

**自证**

```bash
pnpm --filter @saas/api exec vitest run src/common/interceptors/audit.interceptor.spec.ts
```

先看它红在哪——若报「record 未被调用」，说明 spec 里的元数据还是字符串形状，改 spec（第 5 步统一补新用例）。

## 第 4 步 后端接口

### 4.1 `modules/audit/audit.controller.ts`（新增）

```ts
@Controller('audit-logs')
export class AuditController {
  constructor(private readonly audit: AuditService) {}

  @Get()
  @Roles('owner', 'admin')
  list(@Query({ schema: auditLogQuerySchema }) query: AuditLogQuery): Promise<AuditLogListResult> {
    return this.audit.list(query);
  }
}
```

**不加 `@SkipTenant()`**：要按租户过滤，必须让 `TenantGuard` 建立上下文。这跟 05 的邀请接受侧相反（那里调用时用户还没有租户）。

`audit.module.ts` 的 `controllers` 加上它——注意 `AuditModule` 是 `@Global`，但**全局模块不会自动注册 controller**，必须显式列出。

### 4.2 `service.list`

正文见方案 §7.4.4。四个要点：

1. `tenantId` 从 `tenantContext.getStore()?.tenantId` 取，取不到抛 `ForbiddenException({ code: ERROR_CODES.TENANT_MISMATCH })`。**不要**从 `req.query` / header 读——那会绕过 `TenantGuard` 已经做过的 membership 校验。
2. `where` 必须显式带 `tenantId`。`AuditLog` **不在** `TENANT_SCOPE` 白名单，扩展不会注入；漏写不报错，只是把别租户的记录一起返回。
3. `count` 与 `findMany` **共用一个 where 变量**。各写一份，改动时必然漏一处，症状是「翻到第 3 页突然空了，总数却写着 60」。
4. 排序 `[{ createdAt: 'desc' }, { id: 'desc' }]`。只按时间排，同秒多条时 PG 不保证稳定顺序，翻页会重复。

### 4.3 映射函数 `toItem`

`detail` 是 jsonb，可能是 `null`、可能是任意 JSON、历史数据里甚至可能有非对象值。三个摊平字段都要窄化：

```ts
const detail = (row.detail ?? {}) as Record<string, unknown>;
const num = (v: unknown) => (typeof v === 'number' ? v : null);
const str = (v: unknown) => (typeof v === 'string' ? v : null);
```

**不要**写 `(row.detail as { path: string }).path`——历史数据里 `detail` 为 null 时这里直接抛，整页 500。

### 4.4 昵称批量取

```ts
const actors = await this.prisma.user.findMany({
  where: { id: { in: [...new Set(rows.map((r) => r.actorUserId))] } },
  select: { id: true, nickname: true, email: true },
});
```

只调一次。写成 `rows.map(async (r) => await this.prisma.user.findUnique(...))` 就是 20 次往返，Neon 上会明显变慢。

**自证**

```bash
pnpm --filter @saas/api typecheck
# 起服务后（带一个真实 token + X-Tenant-Id）
curl -s "$BASE/audit-logs?pageSize=3" -H "Authorization: Bearer $TOKEN" -H "X-Tenant-Id: $TID" | jq
# 期望 200 + { items: [...], total, page, pageSize }
# 再用 member 角色调一次 → 403 ROLE_DENIED；不带 X-Tenant-Id → 403 TENANT_MISMATCH
```

### 7.2 `page.tsx`

`ProTable` + `Drawer`。列定义见方案 §7.3.2，实现上四个点：

| 点 | 做法 |
|---|---|
| 时间范围 | 单独一列，`valueType: 'dateRange'` + `hideInTable: true` + `initialValue: [今天-29天, 今天]`，`search.transform` 返回 `{ from, to }`（`startOf('day')` / `endOf('day')` 后 `toISOString()`）。ProTable 会把 transform 的返回值 merge 进请求参数 |
| 操作者下拉 | 页面里 `useQuery(['members'], memberApi.list)`，把 `members` 映射成 `valueEnum`（key 用 `userId`，text 用 `nickname`）。**不要**用列的 `request`——它会和主表的 request 抢 loading |
| 动作下拉 | 从 `AUDIT_ACTION_LABELS` 生成 `valueEnum`，label 前加域前缀（「成员 · 移除成员」），17 项扁平即可 |
| 对象列 | `objectName` → `${AUDIT_OBJECT_TYPE_LABELS[objectType] ?? objectType} · ${objectId.slice(0, 8)}` → `'—'`（`objectType` 为 null 时直接跳过这一层，否则索引访问拿不到值）；`objectType === 'resource'` 且有 id 时渲染为链接到 `/app/resources/${id}` |
| 详情抽屉 | 受控 `open` + `onClose`，内容用 `Descriptions`（`column={1}`）。`objectId` 在抽屉里显示**完整 id**，表格里才截断——排查时要能复制完整值 |

**易错点**

- `request` 里 `params.from` / `params.to` 可能为 `undefined`，构造查询对象时用展开而不是显式赋 `undefined`——axios 会把 `undefined` 的字段直接丢掉，一般没事，但若传了空串后端会 422（见第 1 步）。
- `params.action` / `params.result` 来自 `valueEnum`，值是 key（动作码 / `success|failed`），不要再做一层映射。
- 失败的 Tag 用 `status="error"`，成功用 `success`；状态码放 `Tooltip`，别塞进表头。
- `ProTable` 首屏是异步渲染，测试与自查都用 `findBy*`。
- `rowKey="id"` 别漏：审计记录没有天然唯一列上的语义 name，漏了控制台会报 key 警告，展开/抽屉的选中态也会错行。

**自证**：起 dev server，owner 账号打开 `/app/audit-log` 看到数据；把 `pageSize` 改成 1 翻两页看有没有重复行。

## 第 9 步 门禁与手工自测

```bash
pnpm --filter @saas/shared build
pnpm turbo run lint typecheck test
```

**手工自测四条**（方案 §7.5.3 的浓缩版）

1. 造数据：owner 移除一个成员 → 审计页最新一条显示「移除成员 / 操作者昵称 / 被移除者昵称 / 成功」。
2. 越权：同一个账号切到另一个团队，列表里应只有那个团队自己的记录。
3. 失败记录：对 owner 执行「改角色」（预期 409）→ 出现一条红色「失败」，状态码 409，对象只有 id 没有名字。
4. 权限：member 账号侧栏无「审计日志」，直连 `/app/audit-log` 看到 403 页。

进 M2 收口前跑一次旧数据对照：

```sql
SELECT action, object_type, object_id,
       detail->>'objectName' AS object_name,
       detail->>'actorRole'  AS actor_role
FROM audit_logs WHERE tenant_id = '<tid>' ORDER BY created_at DESC LIMIT 10;
```

改造前这四列全 NULL，改造后新产生的记录都有值（对象信息与角色快照）。**历史记录不回填**（方案 §7.4.5 / §7.4.6）。

再验一条快照语义（这条只能用真人操作验）：把某人的角色改掉，回头看他**改之前**的那条审计记录 —— 角色 Tag 必须还是旧值。若跟着变了，说明有人把快照改回了读侧 join。
