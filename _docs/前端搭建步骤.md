以上组合已在临时工程 `/tmp/smoke` 完整跑通 `pnpm install → tsc → vite build → vitest → eslint`。验证中暴露的 6 个坑已全部修掉，**直接抄步骤 1–9 不会遇到**：

| # | 现象 | 根因 | 本文档对应处置 |
|---|------|------|--------------|

### 1.2 pnpm-workspace.yaml（注意 pnpm 11 的写法变更）

```yaml
packages:
  - "apps/*"
  - "packages/*"

allowBuilds:
  esbuild: true
  prisma: true            # 后端：Prisma CLI 下载 query engine
  "@prisma/client": true  # 后端：Prisma client 生成相关
  "@swc/core": true       # 后端：unplugin-swc 的原生二进制
  "@node-rs/bcrypt": true # 后端：预编译 bcrypt 二进制
```

> **pnpm 11 变更**：旧版 `onlyBuiltDependencies` / `neverBuiltDependencies` 已全部移除，改用 `allowBuilds` 映射（键为包名，值为 `true`/`false`）。
> 写在 `package.json` 的 `pnpm` 字段里会被忽略并告警，**只有 `pnpm-workspace.yaml` 生效**。
> 若安装时报 `ERR_PNPM_IGNORED_BUILDS`，执行 `pnpm approve-builds` 交互勾选后把生成的配置提交进版本库。
> `prisma` / `@prisma/client` / `@swc/core` / `@node-rs/bcrypt` 四项是**后端 `apps/api` 需要的**（见《后端实施指南》§1.2），一次写全免得后端开工时再改。

### 1.3 turbo.json（字段是 `tasks`，不是 `pipeline`）

```json
{
  "$schema": "https://turborepo.dev/schema.json",
  "tasks": {
    "build": { "dependsOn": ["^build"], "outputs": ["dist/**"] },
    "typecheck": { "dependsOn": ["^build"] },
    "lint": { "dependsOn": ["^build"] },
    "test": { "dependsOn": ["^build"], "outputs": [] },
    "dev": { "cache": false, "persistent": true },
    "preview": { "cache": false, "persistent": true },
```

> turbo 2.x 已把 1.x 的 `pipeline` 改名为 `tasks`。沿用旧博客的 `pipeline` 配置会直接报 `Found 'pipeline' field instead of 'tasks'`。
> `preview` / `clean` 两个 task 是为后端 `apps/api` 预留的（后端指南 §1.3 会用到）：`preview` 服务 `vite preview`，`clean` 供 `pnpm clean`（api 的 clean 要同时删 `dist` 与 `src/generated/prisma`）。

## 2. 步骤 2：packages/shared 契约包

契约同源是本项目的核心工程主张（知识点 M1-02），前端与后端引用同一份类型与校验。

### 2.1 packages/shared/package.json

```json
{
  "name": "@saas/shared",
  "version": "0.0.0",
  "private": true,
  "type": "module",
  "exports": { ".": "./src/index.ts" },
  "scripts": {
    "build": "tsc -p tsconfig.build.json",
    "typecheck": "tsc --noEmit"
  },
  "dependencies": { "zod": "4.6.7" },
  "devDependencies": { "typescript": "6.0.3" }
}
```

> `exports` 直接指向 `src/index.ts`（源码级引用），免去「改 shared 要重装/重建」的问题，Vite 直接编译 TS 源码。代价是 NestJS 侧需用 ts-node/tsc 编译策略——若后端要求 dist 产物，把 `exports` 改为条件导出即可。

### 2.2 packages/shared/tsconfig.json

```json
{

    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "skipLibCheck": true,
    "noEmit": true
  },
  "include": ["src"]
}
```

### 2.3 packages/shared/tsconfig.build.json

```json
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "noEmit": false,
    "declaration": true,
```

### 2.4 首批共享契约（起步最小集，后续按域扩充）

`packages/shared/src/index.ts`：
```ts
import { z } from "zod";

export const ROLE = {
  owner: "owner",
  admin: "admin",
  member: "member",
} as const;
export type Role = (typeof ROLE)[keyof typeof ROLE];

export const loginSchema = z.object({
  email: z.email(),
  password: z.string().min(8),
});
export type LoginInput = z.infer<typeof loginSchema>;

export interface ApiSuccess<T> {
  success: true;
  data: T;
  message: string;
  timestamp: string;
}

export interface ApiFailure {
  success: false;
  error: { code: string; message: string; details?: unknown };
}
```

> **zod 4 变更点**：`z.string().email()` 已移除，必须用顶层 `z.email()`；`error` 自定义消息写法从 `{ message }` 改为 `{ error }`。
> 后续按 TSD §5.12 错误码表补 `errors.ts`（统一错误码枚举），按 §4.6 补权限矩阵常量。

> ⚠️ **拆分多文件时的硬约束（与《后端实施指南》§1.4 对齐）**
> M1 阶段 `index.ts` **保持单文件**。当它超过 ~300 行、需要按域拆分时：
> 1. **所有相对导入必须带 `.js` 后缀** —— `export * from './schemas/auth.js';`
> 2. 原因：后端 `nest build` 用 tsc 且 `moduleResolution: nodenext`，**强制要求** `.js` 后缀；
>    而 Vite 的 `moduleResolution: bundler` **同时支持** `.js` → `.ts` 的解析。
>    → **带 `.js` 后缀是两端唯一都能跑的写法**。
> 3. `exports` 字段**不用改**（仍指向 `./src/index.ts`）。
> 4. 拆分后需跑一次 `pnpm -F @saas/shared build` 验证类型产物正常。

### 3.2 apps/web/vite.config.ts

```ts
import path from "node:path";

  plugins: [react()],
  resolve: {
    alias: { "@": path.resolve(__dirname, "src") },
```

```tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { RouterProvider } from "react-router";
import { ConfigProvider, App as AntdApp } from "antd";
import zhCN from "antd/locale/zh_CN";
import { router } from "@/app/router";
import "@/styles/global.css";

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 30_000,
      retry: 1,
      refetchOnWindowFocus: false,
    },
  },
});

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <QueryClientProvider client={queryClient}>
      <ConfigProvider locale={zhCN} theme={{ token: { colorPrimary: "#1677ff", borderRadius: 6 } }}>
        <AntdApp>
          <RouterProvider router={router} />
        </AntdApp>
      </ConfigProvider>
    </QueryClientProvider>
  </StrictMode>,
);
```

装配顺序对应 TSD §4.1：`QueryClientProvider → RouterProvider → ConfigProvider(zhCN) → App 全局错误边界`。
`antd` 的 `App` 组件必须包在 `ConfigProvider` 内，用于承载 `message` / `notification` / `Modal` 静态方法的上下文（antd 5.13+ 起静态方法脱离上下文会报警告）。

## 6. 步骤 6：路由与页面骨架

`apps/web/src/app/guards/RequireAuth.tsx`（守卫组件独立成文件，避免与路由对象混在一个文件）：


`apps/web/src/app/router.tsx`（先落地两条路由打通链路，12 屏在 M2–M5 逐步填充）：

```tsx
import { lazy, Suspense } from "react";
import { createBrowserRouter, Navigate } from "react-router";
import { Spin } from "antd";
import { LoginPage } from "@/pages/LoginPage";
import { DashboardPage } from "@/pages/DashboardPage";
import { RequireAuth } from "@/app/guards/RequireAuth";

const ResourcesPage = lazy(() => import("@/pages/ResourcesPage"));

const router = createBrowserRouter([
  { path: "/login", element: <LoginPage /> },
  {
    path: "/app",
    element: (
      <RequireAuth>
        <DashboardPage />
      </RequireAuth>
    ),
    children: [
      { index: true, element: <DashboardPage /> },
      {
        path: "resources",
        element: (
          <Suspense fallback={<Spin />}>
            <ResourcesPage />
          </Suspense>
        ),
      },
    ],
  },
  { path: "/", element: <Navigate to="/app" replace /> },
]);

export { router };
```

**路由导入约定**（锁 react-router 7.18.4 的原因之一）：

| 用途 | 从哪导入 |
|------|---------|
| `createBrowserRouter` / `Navigate` / `Link` / `useNavigate` | `react-router` |
| `RouterProvider` | `react-router`（7.x 主入口已导出）或 `react-router/dom` |
| 组件 | 全部从 `react-router` 导入 |

> 不要写 `react-router-dom`——那是 v6→v7 的兼容垫片，v8 已删除该包，提前用会形成迁移债。

**路由表全量（TSD §4.1，后续按里程碑填充）**：

```

│  └─ /app/resources/:id        member+
```

## 7. 步骤 7：会话状态与页面示例

`apps/web/src/stores/session.ts`（会话状态用 Zustand，接口数据用 TanStack Query，分层不可混）：

```ts
import { create } from "zustand";
import type { Role } from "@saas/shared";

interface SessionState {
  accessToken: string | null;
  currentTenantId: string | null;
  role: Role | null;
  setSession: (s: Partial<Omit<SessionState, "setSession" | "clear">>) => void;
  clear: () => void;
}

export const useSessionStore = create<SessionState>((set) => ({
  accessToken: null,
  currentTenantId: null,
  role: null,
  setSession: (s) => set(s),
  clear: () => set({ accessToken: null, currentTenantId: null, role: null }),
}));
```

> access token 只存内存，**不进 localStorage**（防 XSS 窃取长效凭证）；refresh token 由后端放 httpOnly cookie，前端不可读。详见 TSD §4.4。

## 9. 步骤 9：产物体积与后续待办

### 9.1 体积基线（实测）

上述配置下的首次构建产物：

| chunk | 原始 | gzip |
|-------|------|------|
| antd（含 ProComponents + icons） | 1,760 KB | 569 KB |
| index（含业务代码 + antd 运行时依赖） | 146 KB | 45 KB |
| react（含 react-dom + react-router） | 102 KB | 34 KB |

**antd chunk 超过 500 KB 警戒线**，Vite 会告警。这是把 antd 整包打进一个 manualChunk 的必然结果。M1 阶段可接受（演示级不设硬指标），但要在此记录，改进方向有两条：

1. **拆包**：把 `@ant-design/pro-components` 与 `antd` 分成两个 chunk，避免所有页面都被 antd 阻塞；
2. **按需引入**：AntD 6 默认支持 CSS 变量与组件级按需，配合 `import { Button } from "antd"` 的 tree-shaking，把 `manualChunks` 中的 antd 项去掉，改由 Vite 自动分包。

M6 上线前按 TSD §4.8 要求实测 LCP/CLS 并打印体积报告再定稿。

## 10. 常见坑速查

| 症状 | 根因 | 处置 |
|------|------|------|
| `Found 'pipeline' field instead of 'tasks'` | turbo 1.x 配置 | 改名 `tasks` |
| `ERR_PNPM_IGNORED_BUILDS` | pnpm 11 默认拦截构建脚本 | `pnpm approve-builds` + 提交 `allowBuilds` |
| `pnpm` 字段里的 `onlyBuiltDependencies` 不生效 | pnpm 11 已移除该字段 | 改 `pnpm-workspace.yaml` 的 `allowBuilds` |
| `TS5101: 'baseUrl' is deprecated` | TS 6 废弃 baseUrl | 删 baseUrl，`paths` 用 `./src/*` |
| `TS2882: CSS side-effect import` | 缺 vite/client 类型 | tsconfig `types` 加 `vite/client` |
| `TS2769: 'test' does not exist in UserConfigExport` | 从 `vite` 导入 defineConfig | 改从 `vitest/config` 导入 |
| 测试报 `matchMedia is not defined` | jsdom 未实现 | test-setup.ts 补 mock |
| 测试报 `Cannot find package '@testing-library/dom'` | RTL 的 peer 未装 | 显式加 devDep |
| ESLint 报 `Cannot find package '@eslint/js'` | flat config 依赖未声明 | 显式加 devDep |
| antd 样式错乱 / 双树告警 | 同时装了 pro-components v2 子包与 v3 单体包 | `pnpm why @ant-design/pro-form` 检查，只留单体包 |
| `z.string().email is not a function` | zod 4 移除该方法 | 改顶层 `z.email()` |
| `Cannot find module 'react-router-dom'` | v8 已删除该包 | 从 `react-router` 导入 |
| antd 静态方法不生效 | 缺 `<App>` 包裹 | ConfigProvider 内加 `App` 组件 |
| 类型不同步（改了 shared 前端不报错） | shared 未被引用或未重装 | 确认 `exports` 指向源码 + `pnpm install` |
