## 0. 本文档的组织方式

### 0.1 三段式渐进流程

后端实施按**「拿到能跑的骨架 → 按项目需要改造骨架 → 加工程化基建」**推进，每一步都结束于一个可验证状态：

| 段 | 步骤 | 主题 | 结束时能做什么 |
|---|---|---|---|
| **一、框架搭建** | 步骤 1 | 生成 NestJS 12 脚手架 | 服务能起、`GET /` 返回 Hello World |
| | 步骤 2 | 接入 monorepo | `apps/api` 成为 `@saas/api` workspace 成员，`turbo run build` 通过 |
| **二、改造骨架** | 步骤 3 | 按项目需要改脚手架默认内容 | 目录分层成型、Hello World 被替换成健康检查、契约同源打通 |
| | 步骤 4 | 配置层与全局装配 | 统一响应 / 统一错误 / Swagger / fail-fast 生效 |
| **三、工程化基建** | 步骤 5 | Lint 与格式化统一 | 前后端同一套 ESLint 10 flat config |
| | 步骤 6 | 数据库接入（Prisma 7） | 23 张表落库、seed 造出演示数据、`/health/db` 真实查库 |
| | 步骤 7 | 认证 + 多租户 + RBAC | 双令牌登录、跨租户拦截、角色矩阵生效 |
| | 步骤 8 | 资源 CRUD + 回收站 | 业务域第一个样板跑通 |

### 0.2 每步的固定结构

每个步骤都按同一套骨架写，便于对照执行：

```
步骤 N：<主题>
├── 目标           —— 这一步结束时系统是什么样
├── 做什么         —— 分小节，给具体命令/代码
├── 重要文件       —— 本步涉及的关键文件完整内容（可直接复制）
└── 验收           —— 必跑的验证命令 + 通过标准
```

> **为什么要给完整文件内容**：本项目大量代码要靠复制粘贴落地，给片段会让拼接出错。关键文件一律给完整内容（含 import 路径、`.js` 后缀、缩进）。

### 0.3 路径基准约定

- 带 `apps/api/`、`packages/shared/` 前缀的路径，**相对仓库根**；
- 不带前缀的路径，**相对所在包根**（小节标题已注明包根）；
- 本文档所有代码块中的路径、文件内容均为**已实测**（2026-10-29），非推测。

### 1.2 四条与旧版文档冲突、但实测成立的结论

| # | 旧版结论 | 实测结果 | 依据 |
|---|---|---|---|
| 1 | 「必须装 `unplugin-swc` + 设 `oxc: false`，否则 DI 全线崩」 | **不需要**。当前 `apps/api` 未装任何 SWC，测试直接通过 | 运行时探针：`Reflect.getMetadata('design:paramtypes', AppController)` = `[ [class AppService] ]`，真实类型已产出。Vite 8.3.5 的 oxc 转换器会自行读取 `tsconfig.json` 的 `experimentalDecorators` / `emitDecoratorMetadata` |

## 2. 步骤 1：生成 NestJS 12 脚手架

> **目标**：用官方 CLI 在 `apps/api` 落下一套 NestJS 12（ESM + Vitest）骨架，此时它还只是个独立项目，尚未接入 monorepo。

### 2.1 执行生成命令

在**仓库根**执行：

```bash
cd /Users/lishun/Desktop/workspace/saas-starter

pnpm dlx @nestjs/cli@12.0.10 new api \
  --directory apps/api \
  --package-manager pnpm \
  --language TS \
  --strict \
  --skip-git \
  --no-observe
```

**逐个参数的意思**（源码位置：`@nestjs/cli@12.0.10` 的 `commands/new.command.js`）：

| 参数 | 作用 | 实测确认 |
|---|---|---|
| `pnpm dlx @nestjs/cli@12.0.10` | 临时下载并执行指定版本 CLI，**不污染仓库依赖** | 显式锁版本，避免 CLI 升级带来模板变化 |
| `new api` | 项目名 `api`。CLI 会用 kebab-case 规范化后作为默认目录名 | 本项目用 `--directory` 覆盖了目录 |
| `--directory apps/api` | **目标落盘目录**。生成物直接写在 `apps/api/`，**不会**产生 `apps/api/api/` | dry-run 实测输出全部为 `CREATE apps/api/...` |
| `--package-manager pnpm` | 安装依赖用 pnpm（生成 `pnpm-lock.yaml`、写 `packageManager` 字段） | 免去手改 |
| `--language TS` | 语言，可选 `TS` / `JS`。内部会归一化为 `ts` | 大小写不敏感 |
| `--strict` | 开启 TS strict 模式 | 模板写入 `"strict": true` |
| `--skip-git` | 跳过 `git init` + `.gitignore` 生成 | **本项目必须加**：仓库根已有 git，嵌套仓库会造成混乱 |
| `--no-observe` | 跳过 `@nestjs/observe` 遥测集成的交互提问 | 避免 CLI 卡在交互提示上；不加则终端会停下来问「是否接入 Observe」 |

> **实测补充**：不加 `--no-observe` 时，CLI 在非交互环境（CI、管道输入）会自动跳过提问，但在交互式终端会**停下等待输入**。加上它可保证一条命令跑到底。

### 2.2 生成结果确认（实测清单）

以下是 `@nestjs/schematics@12.0.0` 模板源码 `files/ts-esm/` 的实际内容（ESM + TS 变体）：

| 文件 | 关键内容 |
|---|---|
| `package.json` | `"type": "module"`；`test: vitest run`；`lint: oxlint src/ test/`；依赖 `@nestjs/common ^12.0.1`；devDeps 含 `vitest ^4.1.2` / `vite-tsconfig-paths ^5.1.4` / `typescript ^6.0.2` / `oxlint ^1.58.0`（**均为脚手架默认值，改造后应升到 vitest 5 / 删 oxlint**） |
| `tsconfig.json` | `module: nodenext`、`moduleResolution: nodenext`、`experimentalDecorators: true`、`emitDecoratorMetadata: true`、`types: ["vitest/globals","node"]`、`strictPropertyInitialization: false` |
| `vitest.config.ts` | **仅** `plugins: [tsconfigPaths()]`，无 SWC（但本项目 Vite 8 下也够用，见 §1.2 第 1 条） |
| `vitest.config.e2e.ts` | 同上，`include: ['**/*.e2e-spec.ts']` |
| `nest-cli.json` | `sourceRoot: src`、`deleteOutDir: true` |
| `oxlint.json` + `.prettierrc` | 脚手架默认用 oxlint，**步骤 5 会换掉** |
| `src/*.ts` | 相对导入**带 `.js` 后缀**（`import { AppModule } from './app.module.js'`）——ESM 规范要求，全项目保持一致 |

> **必须保留 `emitDecoratorMetadata: true`**：NestJS 的依赖注入靠它解析构造参数类型，删掉则 DI 全线失败。

>
> | 组合 | `design:paramtypes` | NestJS DI |
> |---|---|---|

>
> **前端同步升级**：`apps/web/package.json` 的 `vite` 也要从 `^7.3.7` 改为 `^8.3.5`，两个包才是真统一。

```json
      "pnpm --filter web exec prettier --write"

  }
}
```

**重要文件**：`apps/api/src/common/filters/http-exception.filter.ts`

```ts
import {
  ArgumentsHost,
  Catch,
  ExceptionFilter,
  HttpException,
  HttpStatus,
  Logger,
} from '@nestjs/common';
import { ERROR_CODES } from '@saas/shared';
import type { Request, Response } from 'express';

interface NormalizedError {
  status: number;
  code: string;
  message: string;
  details?: unknown;
}

const STATUS_TO_CODE: Record<number, string> = {
  [HttpStatus.BAD_REQUEST]: ERROR_CODES.VALIDATION_FAILED,
  [HttpStatus.UNAUTHORIZED]: ERROR_CODES.UNAUTHORIZED,
  [HttpStatus.FORBIDDEN]: ERROR_CODES.FORBIDDEN,
  [HttpStatus.NOT_FOUND]: ERROR_CODES.NOT_FOUND,
  [HttpStatus.CONFLICT]: ERROR_CODES.SUBSCRIPTION_STATE_INVALID,
  [HttpStatus.UNPROCESSABLE_ENTITY]: ERROR_CODES.VALIDATION_FAILED,
  [HttpStatus.TOO_MANY_REQUESTS]: ERROR_CODES.RATE_LIMITED,
  [HttpStatus.INTERNAL_SERVER_ERROR]: ERROR_CODES.INTERNAL_ERROR,
};

function normalizeError(exception: unknown): NormalizedError {
  if (exception instanceof HttpException) {
    const status = exception.getStatus();
    const payload = exception.getResponse();

    if (typeof payload === 'object' && payload !== null) {
      const obj = payload as Record<string, unknown>;
      const code =
        typeof obj.code === 'string'
          ? obj.code
          : (STATUS_TO_CODE[status] ?? ERROR_CODES.VALIDATION_FAILED);
      const message = typeof obj.message === 'string' ? obj.message : exception.message;
      const details = obj.details;
      return { status, code, message, details };
    }

    return {
      status,
      code: STATUS_TO_CODE[status] ?? ERROR_CODES.VALIDATION_FAILED,
      message: typeof payload === 'string' ? payload : exception.message,
    };
  }

  return {
    status: HttpStatus.INTERNAL_SERVER_ERROR,
    code: ERROR_CODES.INTERNAL_ERROR,
    message: 'Internal server error',
  };
}

@Catch()
export class HttpExceptionFilter implements ExceptionFilter {
  private readonly logger = new Logger(HttpExceptionFilter.name);

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const res = ctx.getResponse<Response>();
    const req = ctx.getRequest<Request>();

    const { status, code, message, details } = normalizeError(exception);

    if (status >= 500) {
      this.logger.error(
        `${req.method} ${req.url} → ${status} ${code}`,
        exception instanceof Error ? exception.stack : String(exception),
      );
    }

    res.status(status).json({
      success: false,
      error: {
        code,
        message,
        details: process.env.NODE_ENV === 'production' ? undefined : details,
      },
      timestamp: Date.now(),
    });
  }
}
```

> **约定**：业务代码抛 `new ForbiddenException({ code: 'ROLE_DENIED', message: '...' })`——**用错误码而非状态码**表达语义。状态码只做 HTTP 语义映射。完整错误码表见《技术方案设计》§5.12，错误码常量应放 `packages/shared/src/errors.ts` 供前端复用（步骤 7 补）。

```ts
import { StandardSchemaValidationPipe } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { NestFactory } from '@nestjs/core';
import { DocumentBuilder, SwaggerModule } from '@nestjs/swagger';
import { AppModule } from './app.module.js';
import { HttpExceptionFilter } from './common/filters/http-exception.filter.js';
import { TransformInterceptor } from './common/interceptors/transform.interceptor.js';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  const config = app.get(ConfigService);

  app.setGlobalPrefix('api/v1');

  // Zod schema 校验（schema 来自 @saas/shared，与前端同源）

  // 统一响应 / 统一错误

  app.useGlobalFilters(new HttpExceptionFilter());

  // NestJS 12 内置安全头（等价 Helmet 默认集）
  app.useSecurityHeaders();

  app.enableCors({
    origin: config.getOrThrow<string[]>('corsOrigins'),
    credentials: true, // refresh token 走 httpOnly cookie，必须开
  });

  // Swagger：仅非生产开放
  if (config.get<string>('nodeEnv') !== 'production') {
    const doc = SwaggerModule.createDocument(
      app,
      new DocumentBuilder()
        .setTitle('SaaS Starter API')
        .setDescription('SaaS Starter 后端 API')
        .setVersion('1.0')
        .addBearerAuth()
        .build(),
    );
    SwaggerModule.setup('docs', app, doc);
  }

  await app.listen(config.getOrThrow<number>('port'));
}

await bootstrap();
```

### 6.3 根目录放一份 ESLint 配置？——可以，实测支持

**问题**：`apps/web` 和 `apps/api` 各有一份 `eslint.config.ts`，能不能合并成根目录一份？

**结论：可以。** 实测确认 ESLint 10 会**向上查找父目录**的 flat config（从子目录执行 `eslint src/`，能加载到根目录的 `eslint.config.ts`——实测报错提示需要 `jiti`，恰好证明它找到了根配置）。

**但仍建议保持「两份」，理由**：

| 维度 | 两份（各包一份） | 一份（根目录统一） |
|---|---|---|
| 规则差异 | 各包可定制（web 有 react-hooks/react-refresh，api 无） | 需要在同一个文件里用 `files: ['apps/web/**']` 分流，可读性下降 |
| 依赖位置 | 插件装在用它的包内，pnpm 隔离下解析清晰 | 插件必须装在根，跨包共享后 `files` 分流易错 |
| 心智负担 | 「每个包管自己的 lint」 | 「一个文件管全栈」 |
| `tsconfigRootDir` | 每份独立设置，互不干扰 | 一份文件里要按包切换 `tsconfigRootDir` |

**建议方案：保持两份，但抽出共享基线到 `packages/`**（若将来规则变多再做，现在两份各自 30 行足够）。

> **补充**：根目录**可以**放一份 `eslint.config.ts` 作为「兜底」，专门用于 `packages/shared` 这类无独立 lint 配置的包——但 `packages/shared` 目前也不需要 lint（纯类型 + schema，无运行时逻辑）。

### 7.4 `prisma7.config.ts`

**重要文件**：`apps/api/prisma7.config.ts`

```ts
import 'dotenv/config';
import { defineConfig, env } from 'prisma/config';

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: {
    path: 'prisma/migrations',
    seed: 'tsx prisma/seed.ts',
  },
  datasource: {
    url: env('DATABASE_URL'),
    // 迁移需要直连（绕开 PgBouncer / Neon 池化）；本地 PG 可留空
    shadowDatabaseUrl: process.env.SHADOW_DATABASE_URL,
  },
});
```

> **迁移走直连的做法**（与《部署运维手册》§4 的 `DIRECT_DATABASE_URL` 约定对齐）：CI 与生产执行 `prisma migrate deploy` 时，把 `DATABASE_URL` 指向**直连地址**；运行时再切回池化地址。Neon 池化地址不支持 `prepared statement`（报 `prepared statement "s0" already exists`），这是最常见的迁移失败原因。
>
> 换言之：**`DATABASE_URL` 在迁移时刻 = 直连，在应用运行时刻 = 池化**。

### 7.5 Prisma 7 的六处破坏性变更

| 变更 | v6 写法 | v7 写法 |
|---|---|---|
| Generator | `provider = "prisma-client-js"` | `provider = "prisma-client"` + **必填** `output`（生成物进 `src/generated/prisma`，不落 node_modules） |
| 配置文件 | `prisma.config.ts` | **`prisma7.config.ts`** |
| 连接串 | schema 里 `datasource.url = env(...)` | 移至 `prisma7.config.ts` 的 `datasource.url`（schema 中 url/directUrl/shadowDatabaseUrl 已废弃） |
| 客户端构造 | `new PrismaClient()` | **必须传驱动适配器**：`new PrismaClient({ adapter: new PrismaPg({ connectionString }) })` |
| 环境变量 | CLI 自动读 `.env` | 需 `import 'dotenv/config'` 显式加载 |
| 生成与 seed | `migrate dev` 自动 generate + 自动 seed | **两者都不再自动执行**：需显式 `prisma generate` / `prisma db seed` |
| 客户端中间件 | `prisma.$use()` | 已移除 → 只能用 `$extends`（本项目本就规划用扩展，正好） |

> **知识点里的伪代码用的是 `prisma.$use()`，在 Prisma 7 下已不可用**，落地时改为 `$extends`（见步骤 7.9）。

### 7.6 `schema.prisma` 骨架

**重要文件**：`apps/api/prisma/schema.prisma`

```prisma
generator client {
  provider = "prisma-client"
  output   = "../src/generated/prisma"
  // tsx 跑 seed 时需要（否则报 Cannot find module './internal/class.js'）
  importFileExtension = "ts"
}

datasource db {
  provider = "postgresql"
  // url 在 prisma7.config.ts 中配置
}

enum MemberRole {
  owner
  admin
  member
}

enum MemberStatus {
  active
  disabled
  removed
}

model User {
  id              String       @id @default(cuid())
  email           String       @unique
  passwordHash    String       @map("password_hash") @db.VarChar(100)
  nickname        String       @db.VarChar(50)
  avatarUrl       String?      @map("avatar_url") @db.VarChar(500)
  emailVerifiedAt DateTime?    @map("email_verified_at")
  lastLoginAt     DateTime?    @map("last_login_at")
  status          UserStatus   @default(active)
  createdAt       DateTime     @default(now()) @map("created_at")
  updatedAt       DateTime     @updatedAt @map("updated_at")

  memberships Membership[]
  ownedTenants Tenant[]     @relation("TenantOwner")
  @@map("users")
}

model Tenant {
  id         String    @id @default(cuid())
  name       String    @db.VarChar(100)
  logoUrl    String?   @map("logo_url") @db.VarChar(500)
  brandColor String?   @map("brand_color") @db.VarChar(9)
  ownerId    String    @map("owner_id")
  deletedAt  DateTime? @map("deleted_at")
  createdAt  DateTime  @default(now()) @map("created_at")
  updatedAt  DateTime  @updatedAt @map("updated_at")

  owner       User         @relation("TenantOwner", fields: [ownerId], references: [id])
  memberships Membership[]
  @@index([ownerId])
  @@map("tenants")
}

model Membership {
  id           String       @id @default(cuid())
  tenantId     String       @map("tenant_id")
  userId       String       @map("user_id")
  role         MemberRole   @default(member)
  status       MemberStatus @default(active)
  invitedBy    String?      @map("invited_by")
  joinedAt     DateTime     @default(now()) @map("joined_at")
  lastActiveAt DateTime?    @map("last_active_at")
  createdAt    DateTime     @default(now()) @map("created_at")
  updatedAt    DateTime     @updatedAt @map("updated_at")

  tenant Tenant @relation(fields: [tenantId], references: [id], onDelete: Cascade)
  user   User   @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([tenantId, userId])
  @@index([userId])
  @@map("memberships")
}
```

**全库建模纪律**（对应《数据库设计与数据字典》§1）：

1. 表名复数 snake_case，字段 snake_case → Prisma model 用 PascalCase + `@map`/`@@map`
2. 除 `users` / `plans` / `payment_idempotency` / `refresh_tokens` / `email_tokens` 外，**所有表强制含 `tenant_id` + 索引**
3. 金额一律 `*_cents Int`，**全链路无浮点**
4. 时间戳 `TIMESTAMP(3) UTC`，`created_at`/`updated_at` 必备
5. 外键明确 `onDelete`：跨域**不级联**，防误删扩散
6. 枚举取 PG 原生 ENUM，取值与 shared 包常量同源

> 23 张表的完整定义见《数据库设计与数据字典》§3，**逐字照抄**，不要自行发挥字段名。

### 7.8 `PrismaService` 与驱动适配器

**重要文件**：`apps/api/src/prisma/prisma.service.ts`

```ts
import { Injectable, OnModuleDestroy, OnModuleInit } from '@nestjs/common';
import { PrismaPg } from '@prisma/adapter-pg';
import { PrismaClient } from '../generated/prisma/client.js';

@Injectable()

  extends PrismaClient
  implements OnModuleInit, OnModuleDestroy
```

## 8. 步骤 7：认证 + 多租户 + RBAC

### 8.1 认证链路

```
注册 → 发验证邮件（email_tokens, type=verify_email, 15min TTL）
     → 验证通过 → 事务：users.email_verified_at + 创建 tenants + memberships(role=owner)
登录 → 校验 bcrypt(cost≥12) → 签发：
     ├─ accessToken  15min  payload { sub, tenantId?, type:'access' }   Authorization 头
     └─ refreshToken 30d    httpOnly + SameSite=Strict + Secure cookie  服务端存表可吊销
刷新 → 校验有效性 + 未吊销 → 轮转（旧 refresh 吊销，发新对）
登出 → 吊销当前 refresh + 清 cookie
找回密码 → email_tokens(type=reset_password, 30min, 单次有效) → 改密后吊销该用户全部 refresh
```

**登录失败限流**：`@nestjs/throttler` 按 IP + 邮箱双维度（5 次 / 15 分钟），超限返回 `RATE_LIMITED`。

```ts
} from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { IS_PUBLIC_KEY } from '../decorators/public.decorator.js';
import { TokenService } from '../../modules/auth/token.service.js';

export interface AuthUser {
  userId: string;
  tenantId?: string;
}

@Injectable()
export class JwtAuthGuard implements CanActivate {
  constructor(
    private readonly reflector: Reflector,
    private readonly tokenService: TokenService,
  ) {}

  async canActivate(ctx: ExecutionContext): Promise<boolean> {
    const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
      ctx.getHandler(),
      ctx.getClass(),
    ]);
    if (isPublic) return true;

    const req = ctx.switchToHttp().getRequest<Request & { user?: AuthUser }>();
    const header = req.headers.authorization;
    if (!header?.startsWith('Bearer ')) {
      throw new UnauthorizedException({
        code: 'UNAUTHORIZED',
        message: '缺少访问令牌',
      });
    }

    try {
      const payload = await this.tokenService.verifyAccess(header.slice(7));
      req.user = { userId: payload.sub, tenantId: payload.tenantId };
      return true;
    } catch {
      throw new UnauthorizedException({
        code: 'TOKEN_EXPIRED',
        message: '访问令牌已过期或无效',
      });
    }
  }
}
```

### 8.2 多租户行级隔离

> ⚠️ **本小节必须独立完成并独立验证**。框架纪律失效（代码里忘写 `where: { tenantId }`）时，这一层是唯一的兜底。

**重要文件**：`apps/api/src/prisma/tenant.extension.ts`

```ts
import { AsyncLocalStorage } from 'node:async_hooks';
import { Prisma } from '../generated/prisma/client.js';

// 请求级租户上下文
export const tenantContext = new AsyncLocalStorage<{ tenantId: string }>();

// 强制含 tenant_id 的模型白名单
const TENANT_SCOPED = new Set([
  'Resource', 'File', 'AiDocument', 'AiChunk', 'AiConversation', 'AiMessage',
  'Subscription', 'SubscriptionEvent', 'Invoice', 'GatewayTransaction',
  'Notification', 'NotificationPreference', 'AuditLog', 'UsageMonthly',
  'Membership', 'Invitation',
]);

export function tenantScopedExtension() {
  return Prisma.defineExtension({
    name: 'tenant-scope',
    query: {
      $allModels: {
        async $allOperations({ model, operation, args, query }) {
          const ctx = tenantContext.getStore();
          if (!ctx || !TENANT_SCOPED.has(model ?? '')) return query(args);

          const where = (args.where ?? {}) as Record<string, unknown>;
          const extra =
            operation === 'create'
              ? { data: { ...(args.data as object), tenantId: ctx.tenantId } }
              : { where: { ...where, tenantId: ctx.tenantId } };

          return query({ ...args, ...extra } as typeof args);
        },
      },
    },
  });
}
```

**重要文件**：`apps/api/src/common/guards/tenant.guard.ts`

```ts
import {
  CanActivate,
  ExecutionContext,
  ForbiddenException,
  Injectable,
} from '@nestjs/common';

@Injectable()
export class TenantGuard implements CanActivate {
  async canActivate(ctx: ExecutionContext): Promise<boolean> {
    const req = ctx.switchToHttp().getRequest<
      Request & { user?: { userId: string }; tenantId?: string; userRole?: string }
    >();

    const tenantId = req.headers['x-tenant-id'];
    if (typeof tenantId !== 'string' || !tenantId) {
      throw new ForbiddenException({
        code: 'TENANT_MISMATCH',
        message: '缺少租户上下文',
      });
    }

    // membership 校验：用户在该租户存在且 active
    const membership = await this.membersService.findActive(
      req.user?.userId,
      tenantId,
    );
    if (!membership) {
      throw new ForbiddenException({
        code: 'TENANT_MISMATCH',
        message: '无权访问该租户',
      });
    }

    req.tenantId = tenantId;
    req.userRole = membership.role;
    return true;
  }
}
```

> **业务纪律**：**任何 Controller 都不从参数读 tenantId**，只从 `req.tenantId` 取。`X-Tenant-Id` 头由前端 Axios 拦截器自动注入。

**隔离三道防线（缺一不可）**：

1. `TenantGuard` 校验 membership（防越权进入）
2. Prisma Extension 自动合并 `tenantId`（防漏写过滤）—— **第二道防线，代码纪律失效时的兜底**
3. 跨租户越权回归测试（防回归）

> **禁止用子查询 / 原生 SQL 绕过扩展**——扩展只作用于 Prisma Client API，`$queryRaw` 不经过它。聚合统计需显式 `groupBy({ by: ['tenantId'] })` 保证隔离。

**重要文件**：`apps/api/src/common/guards/roles.guard.ts`

```ts
import {
  CanActivate,
  ExecutionContext,
  ForbiddenException,
  Injectable,
} from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import type { Role } from '@saas/shared';
import { ROLES_KEY } from '../decorators/roles.decorator.js';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(ctx: ExecutionContext): boolean {
    const required = this.reflector.getAllAndOverride<Role[]>(ROLES_KEY, [
      ctx.getHandler(),
      ctx.getClass(),
    ]);
    if (!required?.length) return true;

    const role = ctx.switchToHttp().getRequest<Request & { userRole?: Role }>()
      .userRole;
    if (!role || !required.includes(role)) {
      throw new ForbiddenException({
        code: 'ROLE_DENIED',
        message: '当前角色无权执行该操作',
      });
    }
    return true;
  }
}
```

**权限矩阵**（与《技术方案设计》§4.6 同源，常量放 shared 包）：

| 操作 | member | admin | owner |

| 资源增删改 / 上传附件 | ✅ | ✅ | ✅ |
| 回收站管理 / 审计查看 | ❌ | ✅ | ✅ |
| 邀请 / 调角色 / 禁用 / 移除 | ❌ | ✅（admin 不能改 owner） | ✅ |
| owner 转让 | ❌ | ❌ | ✅ |
| 订阅 / 退款 / 账单 | ❌ | ❌ | ✅ |
| 租户设置 | ❌ | ✅ | ✅ |

**边界规则**：admin 可管理 member、不可改动 owner、不可自降级（防租户无主）；owner 转让需目标为 active 成员，事务内角色互换 + 审计。

```ts
import {
  CallHandler,
  ExecutionContext,
  Injectable,
  NestInterceptor,
} from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { Observable, from, switchMap, tap } from 'rxjs';
import { AUDIT_KEY } from '../decorators/audit.decorator.js';
import { AuditService } from '../../modules/audit/audit.service.js';

@Injectable()
export class AuditInterceptor implements NestInterceptor {
  constructor(
    private readonly reflector: Reflector,
    private readonly auditService: AuditService,
  ) {}

  intercept(ctx: ExecutionContext, next: CallHandler): Observable<unknown> {
    const action = this.reflector.getAllAndOverride<string>(AUDIT_KEY, [
      ctx.getHandler(),
    ]);
    if (!action) return next.handle();

    const req = ctx.switchToHttp().getRequest<
      Request & { user?: { userId: string }; tenantId?: string }
    >();
    const started = Date.now();

    return next.handle().pipe(
      tap({
        next: () => {
          void this.auditService.record({
            tenantId: req.tenantId ?? null,
            actorUserId: req.user?.userId,
            action,
            objectType: action.split('.')[0],
            objectId: req.params?.id,
            ip: req.ip,
            result: 'success',
            detail: { durationMs: Date.now() - started },
          });
        },
        error: () => {
          void this.auditService.record({
            tenantId: req.tenantId ?? null,
            actorUserId: req.user?.userId,
            action,
            objectType: action.split('.')[0],
            objectId: req.params?.id,
            ip: req.ip,
            result: 'failed',
            detail: { durationMs: Date.now() - started },
          });
        },
      }),
    );
  }
}
```

```ts
export const ROLE = {
  owner: 'owner',
  admin: 'admin',
  member: 'member',
} as const;

export type Role = (typeof ROLE)[keyof typeof ROLE];

export const loginSchema = z.object({
  email: z.email(),
  password: z.string().min(8),
});

export type LoginInput = z.infer<typeof loginSchema>;

export const resourceCreateSchema = z.object({
  name: z.string().min(1).max(100),
  description: z.string().max(2000).optional(),
  category: z.string().max(50).optional(),
});

export type ResourceCreateInput = z.infer<typeof resourceCreateSchema>;

export const resourceQuerySchema = z.object({
  page: z.coerce.number().int().positive().default(1),
  pageSize: z.coerce.number().int().positive().max(100).default(20),
  q: z.string().max(100).optional(),
  category: z.string().max(50).optional(),
});

export type ResourceQuery = z.infer<typeof resourceQuerySchema>;

export interface ApiSuccess<T> {
  success: true;
  data: T;
  message: string;
  timestamp: number;
}

export interface ApiFailure {
  success: false;
  error: {
    /** 业务错误码（字符串枚举），与《技术方案设计》§5.12 错误码表一致 */
    code: string;
    message: string;
    details?: unknown;
  };
  timestamp: number;
}
```

> ⚠️ **本次修正的一处类型矛盾**：shared 原本把 `ApiFailure.error.code` 定义成 `number`，但后端异常过滤器返回的是**字符串错误码**（`ROLE_DENIED` / `TENANT_MISMATCH` / `VALIDATION_FAILED` 等，见 §5.2）。前端 Axios 拦截器按错误码分支时，`number` 与字符串对不上，TS 会报错。
>
> **已改为 `code: string`**。落地时需同步修改 `packages/shared/src/index.ts`（本步骤会改），错误码常量表也应一并抽出到 `packages/shared/src/errors.ts` 供两端复用。
>
> 相应地，`ApiSuccess` / `ApiFailure` 都应带 `timestamp: number`（毫秒），与后端拦截器、过滤器产出结构完全一致。

> **Zod 4 提示**：`z.email()` 是顶层 API（Zod 3 的 `z.string().email()` 已移除）。
>
> **shared 纪律**：只放纯类型 / 常量 / schema，不放运行时逻辑（不连数据库、不发请求），否则 web/api 构建耦合。
>
> **ESM 后缀纪律**（步骤 8 会把 shared 拆成多文件时生效）：`export * from './errors.js'` 必须带 `.js` 后缀——后端 `tsc` 用 `moduleResolution: nodenext`，**要求** `.js`；前端 Vite（`moduleResolution: bundler`）能正确解析到 `.ts`。两边都兼容。拆分后 `packages/shared/src/index.ts` 顶部需加：
>
> ```ts
> export * from './errors.js';
> ```
