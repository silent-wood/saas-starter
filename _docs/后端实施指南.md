## 0. 执行前必须拍板的 7 个决策

TSD 附录 A.9 约定「M1 动工前统一复核版本锚点」。本指南完成该复核，结论如下——**这 6 项先定，再动代码**，否则中途返工成本最高。

| # | 决策点 | 建议 | 理由与代价 |
|---|--------|------|-----------|
| D1 | NestJS 版本 | **12.2.x**（非文档的 ^11） | v12 提供 Standard Schema 原生校验 → shared 包的 Zod schema 可直接进 `@Body({ schema })`，**契约同源从"两套定义"变成"一份定义"**，正好是本项目的核心卖点。代价：v12 核心包为 ESM，CommonJS 应用仍可用但新项目建议直接上 ESM |
| D2 | Prisma 版本 | **prisma@7 + @prisma/client@7**（非文档的 ^6，且**绝不能用 latest**） | `prisma@latest` 现在指向 **8.0.0-rc.27（RC）**，装上后 CLI 没有 `generate`/`migrate` 命令；Prisma 8 改写了 `$extends` 语义且缺嵌套写入。Prisma 6 仅到 2026-11-19 才有安全补丁。**必须显式 pin 版本号** |
| D3 | Monorepo 编排 | **pnpm workspace + Turborepo，不用 NestJS 自带 monorepo 模式** | NestJS 的 `nest generate app` 会接管目录结构，与 pnpm workspace + turbo 任务图冲突。本项目 apps/api 当普通包管理 |
| D4 | 校验方案 | **Zod 4 + NestJS 12 StandardSchemaValidationPipe**（替代文档的 zod-nest + class-validator 双轨） | 单轨。Zod 4 原生实现 Standard Schema，schema 放 `packages/shared`，后端 `@Body({ schema: SharedSchema })`，前端 RHF 直接消费同一份。代价：Swagger 需额外接 `standardSchemaConverter`（见 §4.4） |
| D5 | 密码哈希 | **`@node-rs/bcrypt`**（替代 `bcrypt`） | 算法与 cost≥12 规范不变，但 node-rs 是预编译二进制，`bcrypt` 是原生模块需 node-gyp 编译 → CI 与 Render/Railway 部署易因编译链失败。零行为差异、零运维成本 |
| D6 | 开发数据库 | **Neon 云库（与部署同构）**，备选本地 PG16+pgvector | Neon 免费版原生支持 pgvector、Prisma 5.10+ 可自动建 shadow DB、免装免运维。备选本地库速度快但 pgvector 与 keg-only 的 postgresql@16 需手工链接 extension 目录 |
| **D7** | **测试转换器** | **Vitest + `unplugin-swc`（必须）+ `oxc: false`** | 见 §2.8。**这是 NestJS 12 脚手架的实测缺口**，不做则单元测试里 DI 全线失败 |

> **版本核对结论表**（实测，非推测）：

| 依赖 | 文档锚点 | 2026-10 实测 | 处置 |
|------|---------|--------------|------|
| NestJS | ^11 | 12.2.0（12.0 于 2026-08-27 发布） | 升 12 |

### 1.1 目录准备

```bash
cd /Users/lishun/Desktop/workspace/saas-starter
mkdir -p apps/api
```

**不要**在根目录执行 `pnpm init` 或重写根 `package.json`——那会覆盖前端已定的版本矩阵。

### 1.2 pnpm-workspace.yaml（追加 allowBuilds）

后端引入的包带**原生构建脚本**，pnpm 11 默认拦截，不显式放行则 `pnpm install` 报 `ERR_PNPM_IGNORED_BUILDS`。

在《前端搭建步骤》已写好的 `pnpm-workspace.yaml` 上**追加**（保留 `esbuild: true`）：

```yaml
packages:
  - "apps/*"
  - "packages/*"

allowBuilds:
  esbuild: true           # 前端 vite 依赖
  prisma: true            # Prisma CLI 的 install 脚本下载 query engine
  "@prisma/client": true  # Prisma client 生成相关
  "@swc/core": true       # unplugin-swc 的原生二进制（见 §2.8，必须）
  "@node-rs/bcrypt": true # 预编译 bcrypt 二进制
```

> **pnpm 11 变更**：旧版 `onlyBuiltDependencies` / `neverBuiltDependencies` 已全部移除，改用 `allowBuilds` 映射（键为包名，值为 `true`/`false`）。写在 `package.json` 的 `pnpm` 字段里会被忽略并告警，**只有 `pnpm-workspace.yaml` 生效**。
> 安装时报 `ERR_PNPM_IGNORED_BUILDS` 时执行 `pnpm approve-builds` 交互勾选，把结果提交进版本库，CI 才能复现同一决策。

### 1.3 turbo.json（追加 preview / clean）

在《前端搭建步骤》的 `turbo.json` 基础上**追加**两个 task（`build` / `typecheck` / `lint` / `test` / `dev` 保持前端原样）：

```json
{
  "$schema": "https://turborepo.dev/schema.json",
  "tasks": {
    "build": { "dependsOn": ["^build"], "outputs": ["dist/**"] },
    "typecheck": { "dependsOn": ["^build"] },
    "lint": { "dependsOn": ["^build"] },
    "test": { "dependsOn": ["^build"], "outputs": [] },
    "dev": { "cache": false, "persistent": true },
    "preview": { "cache": false, "persistent": true },
    "clean": { "cache": false }
  }
}
```

> `build` 依赖 `^build` 是**契约同源能生效的前提**：shared 改了类型，依赖它的 api/web 必须重新构建。
> `preview` 服务 `apps/web` 的 `vite preview`（前端根 `package.json` 已有 `preview` 脚本，turbo 侧要补 task 才能被 `turbo run preview` 调到）。
> `clean` 供 `pnpm clean` 用；api 的 clean 脚本要同时删 `dist` 与 `src/generated/prisma`。

### 1.4 packages/shared（**不改，沿用前端已定结构**）

前端指南已冻结以下内容，**后端照抄，不做任何修改**：

```json
{
  "name": "@saas/shared",
  "version": "0.0.0",
  "private": true,
  "type": "module",
  "exports": { ".": "./src/index.ts" },
  "scripts": {
    "build": "tsc -p tsconfig.build.json",
    "typecheck": "tsc --noEmit"
  },
  "dependencies": { "zod": "4.6.7" },
  "devDependencies": { "typescript": "6.0.3" }
}
```

**为什么后端不改 `exports`**（前端指南留了一句让人自行决定，这里给结论）：

前端把 `exports` 指向 `./src/index.ts`（源码级引用），好处是「改 shared 免重装/重建」。代价是 **Node 的 ESM 解析器无法加载 `node_modules` 里的 `.ts`**——但这个问题**在本项目不成立**，因为：

- pnpm workspace 下 `@saas/shared` 是**符号链接指向 `packages/shared` 本地目录**（`workspace:*`），不是真正的 `node_modules` 包；
- `nest build` 用 **tsc** 编译，TS 解析到软链后会**跟随软链把 `packages/shared/src/*.ts` 一并纳入编译**，产物落到 `dist`；
- 因此运行时加载的是 **tsc 编译后的 `.js`**，不是原始 `.ts`。

**唯一硬约束**：既然 tsc 会跟随软链编译 shared，shared 内部的相对导入必须满足 `nodenext` 的 `.js` 后缀要求。

| 约束 | 写法 | 兼容性 |
|------|------|--------|
| shared 内部相对导入 | `export * from './errors.js'` | ✅ 前端 Vite（`moduleResolution: bundler` 能把 `.js` 解析到 `.ts`）<br>✅ 后端 tsc（`nodenext` **要求** `.js` 后缀） |

> **M1 阶段的落地要求**：`packages/shared/src/index.ts` **保持单文件**（前端指南当前示例就是单文件，尚未触发约束）。
> 一旦要拆成多文件（`enums/`、`schemas/`、`types/`），**所有相对导入必须带 `.js` 后缀**，且需与前端同步一次（前端只改导入写法，不改 `exports`）。
>
> ```ts
> // packages/shared/src/index.ts（拆分后）
> export * from './errors.js';
> export * from './enums/index.js';
> export * from './schemas/auth.js';
> ```

**shared 包内容规划**（后续里程碑持续填充，M1 先落最小集）：

```
packages/shared/src/
├─ index.ts                 # 统一出口（M1 保持单文件）
├─ errors.ts                # 错误码常量（对应 TSD §5.12）
├─ enums/                   # 19 个业务枚举（对应数据字典 §4）
├─ types/                   # 领域类型
└─ schemas/                 # Zod 4 schema（请求校验 + 前端表单共用）
```

> **纪律**：shared 里只放**纯类型 / 常量 / schema**，不放运行时逻辑（不连数据库、不发请求），否则 web/api 构建耦合。
> Zod 4 顶层 API 与 Zod 3 不同：`z.email()`、`z.url()`、`z.uuid()` 独立存在，不要写 `z.string().email()`。

### 1.6 Lint 选型：**统一 ESLint**（对齐前端，见 §0.1 第 6 项）

TSD 原写 ESLint + typescript-eslint，NestJS 12 脚手架默认 **oxlint**（Rust 实现，速度是 ESLint 的百倍量级）。但前端**已用 ESLint 10.13.0 flat config**，若后端用 oxlint，就会出现**两套 lint 栈、两套规则、两套 CI 命令**——这在作品集里是减分项。

**决策：全栈统一 ESLint 10 flat config。**

`apps/api/eslint.config.js`：

```js
import js from '@eslint/js';
import tseslint from 'typescript-eslint';
import prettier from 'eslint-config-prettier';

export default tseslint.config(
  {
    ignores: ['dist/**', 'src/generated/**', 'node_modules/**', 'eslint.config.js'],
  },
  js.configs.recommended,
  ...tseslint.configs.recommended,
  {
    languageOptions: {
      parserOptions: {
        projectService: true,
        tsconfigRootDir: import.meta.dirname,
      },
    },
    rules: {
      '@typescript-eslint/no-explicit-any': 'warn',
      '@typescript-eslint/no-unused-vars': ['error', { argsIgnorePattern: '^_' }],
    },
  },
  prettier,
);
```

`apps/api/package.json` 需追加的 devDeps（与前端版本对齐）：

```json
{
  "devDependencies": {
    "@eslint/js": "10.0.1",
    "eslint": "10.13.0",
    "eslint-config-prettier": "10.1.8",
    "typescript-eslint": "8.72.0",
    "prettier": "3.9.10"
  }
}
```

同时**删除**脚手架生成的 `apps/api/oxlint.json`，并把 `lint` 脚本从 `oxlint src/ test/` 改为 `eslint src test`。

> `typescript-eslint` v8 原生支持 flat config，`tseslint.config(...)` 即可，无需额外 adapter。
> 根 `package.json` 若前端已把 eslint 相关依赖放在根上，后端**不要重复声明**——先查根 `package.json` 再决定放哪（pnpm workspace 下重复声明会出现两份实例，flat config 的 plugin 对象不共享，规则行为可能不一致）。

        message: 'OK',

@Catch()
export class HttpExceptionFilter implements ExceptionFilter {
  constructor(private readonly logger: LoggerService) {}

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const res = ctx.getResponse<Response>();

    const { status, code, message, details } = normalizeError(exception);

    res.status(status).json({
      success: false,
      error: {
        code,
        message,
        details: process.env.NODE_ENV === 'production' ? undefined : details,
      },
      timestamp: new Date().toISOString(),
    });
  }
}
```

### 2.7 测试转换器：为什么脚手架默认配置会失败（**必做**）

> 这是本次实测发现的**头号坑**，不处理则 `pnpm --filter @saas/api test` 必然失败，且报错信息极具误导性（只说"找不到依赖"，不说是元数据问题）。

**问题链条**（每一环都实测过）：

1. NestJS DI 靠 `design:paramtypes` 元数据解析构造参数类型。该元数据**只有 tsc / SWC 能产出**，esbuild 与 Oxc 都做不到完整产出。
2. NestJS 12 脚手架生成的 `vitest.config.ts` **只有 `tsconfigPaths()` 插件，没有 SWC**：
   ```ts
   import { defineConfig } from 'vitest/config';
   import tsconfigPaths from 'vite-tsconfig-paths';
   export default defineConfig({ plugins: [tsconfigPaths()], test: { /* ... */ } });
   ```
3. Vitest 走 Vite 的 TS 转换管线。Vite 7 默认 esbuild —— **esbuild 官方明确不支持 `emitDecoratorMetadata`**（无类型系统，推不出来）。
4. Vite 8 默认换成 Oxc —— 实测：**Oxc 不会自动从 tsconfig 读取 `experimentalDecorators` / `emitDecoratorMetadata`**，必须显式传 `decorator: { legacy: true, emitDecoratorMetadata: true }` 才会产出。

**实测证据**（`oxc-transform` 直接调用，同一份 NestJS 风格代码）：

| 输入 | 输出 |
|------|------|
| 仅传 `tsconfig`（含两个装饰器开关） | **无 `design:paramtypes`** |
| 传 `tsconfig` + `decorator: { legacy: true, emitDecoratorMetadata: true }` | ✅ `design:paramtypes` 正常产出 |

**失败时的真实报错**（极具误导性）：

```
Nest can't resolve dependencies of the AppController (Object, ?).
Please make sure that the argument AppService at index [0] is available
in the AppController context.
```

—— 报的是 `(Object, ?)`，参数类型变成了 `Object`，因为元数据整体缺失。

**解决方案：装 `unplugin-swc`，并按 Vite 版本决定是否关掉 Oxc。**

```bash
cd apps/api
pnpm add -D unplugin-swc @swc/core
```

`apps/api/vitest.config.ts`：

```ts
import { defineConfig } from 'vitest/config';
import tsconfigPaths from 'vite-tsconfig-paths';
import swc from 'unplugin-swc';

export default defineConfig({
  plugins: [
    // SWC 产出 NestJS DI 所需的装饰器元数据
    swc.vite({ module: { type: 'es6' } }),
    // 解析 tsconfig 里的路径别名
    tsconfigPaths(),
  ],
  // Vite 8+ 默认用 Oxc 转换 TS；Oxc 会剥掉 SWC 已产出的元数据，
  // 必须关掉，让 SWC 成为唯一转换器
  oxc: false,
  test: {
    globals: true,
    root: './',
    environment: 'node',
    include: ['**/*.spec.ts'],
  },
});
```

`apps/api/vitest.config.e2e.ts` 同样加 `swc.vite()` 与 `oxc: false`：

```ts
import { defineConfig } from 'vitest/config';
import tsconfigPaths from 'vite-tsconfig-paths';
import swc from 'unplugin-swc';

export default defineConfig({
  plugins: [swc.vite({ module: { type: 'es6' } }), tsconfigPaths()],
  oxc: false,
  test: {
    globals: true,
    root: './',
    environment: 'node',
    include: ['**/*.e2e-spec.ts'],
  },
});
```

> **`oxc: false` 什么时候需要？**
> - **Vite 8+（`vite` ≥ 8.0.0）**：**必须加**。Oxc 是默认转换器，它与 SWC 同时存在时，若不关掉，Oxc 的产物会覆盖/剥离 SWC 产出的元数据 → 症状是"明明装了 SWC 还是报 Object"。
> - **Vite 7（本项目前端锁的版本）**：加上也无害（Vite 7 无 `oxc` 选项，该字段被忽略）。**统一加上，避免将来升 Vite 8 时踩坑。**
>
> **为什么后端跟随前端锁 Vite 7.3.7**（而不是 Vite 8）：
> Vite 8 用 Rolldown + Oxc，**Oxc 的装饰器元数据只"部分支持"**——它依赖类型推断，而 Oxc 不做完整的类型检查，跨文件类型会退化为 `Object`。而 `unplugin-swc` 在 Vite 7 / 8 上都能完整产出元数据。锁 Vite 7 + SWC 的组合是当前最稳的路径。
>
> **补充说明**：Oxc 生成的元数据形如 `typeof AppService === "undefined" ? Object : AppService`——这个 `typeof` 守卫在**运行时是安全的**（类已定义时取真值），但**类型推断失败时会真的退化为 `Object`**，此时 DI 依旧会挂。所以不要依赖 Oxc 的产物。

**验证是否生效**（M1 必做，一次性验证，后续不再纠结）：

```bash

```

脚手架自带的 `app.controller.spec.ts`（用 `Test.createTestingModule` 注入 `AppService`）**通过 = 元数据链路 OK**。
若报 `(Object, ?)` → 回到本节检查 `swc.vite()` 是否注册、`oxc: false` 是否设置。

> **`unplugin-swc` 会读 `tsconfig.json`**：它自动继承 `experimentalDecorators` / `emitDecoratorMetadata`，因此**不要**额外写 `.swcrc` 覆盖（写错比不写更糟）。
> `@swc/core` 是原生二进制，**必须在根 `pnpm-workspace.yaml` 的 `allowBuilds` 里放行**（§1.2 已含）。

### 3.2 Prisma 7 的五处破坏性变更（对照调整）

| 变更 | v6 写法 | v7 写法 |
|------|---------|---------|
| Generator | `provider = "prisma-client-js"` | `provider = "prisma-client"` + **必填** `output`（生成物进 `src/generated/prisma`，不落 node_modules） |
| 连接串 | schema 里 `datasource.url = env(...)` | 移至 `prisma.config.ts` 的 `datasource.url`（schema 中 url/directUrl/shadowDatabaseUrl 已废弃） |
| 客户端构造 | `new PrismaClient()` | **必须传驱动适配器**：`new PrismaClient({ adapter: new PrismaPg({ connectionString }) })` |
| 环境变量 | CLI 自动读 `.env` | 需 `import 'dotenv/config'` 显式加载 |
| 生成与 seed | `migrate dev` 自动 generate + 自动 seed | **两者都不再自动执行**：需显式 `prisma generate` / `prisma db seed` |
| 客户端中间件 | `prisma.$use()` | 已移除 → 只能用 `$extends`（本项目本就规划用扩展，正好） |

> **知识点 M2-03 的伪代码用的是 `prisma.$use()`，在 Prisma 7 下已不可用**，落地时改为 `$extends`（见 §5.2）。TSD §5.4 的表述本来就是 Client Extension，与代码一致，无需改设计。

### 3.4 schema.prisma 骨架

`apps/api/prisma/schema.prisma`（完整 23 张表见《数据库设计与数据字典》§3，此处给关键约定与前几张表）：

```prisma
generator client {
  provider = "prisma-client"
  output   = "../src/generated/prisma"
  // tsx 跑 seed 时需要（否则报 Cannot find module './internal/class.js'）
  importFileExtension = "ts"
}

datasource db {
  provider = "postgresql"
  // url 在 prisma.config.ts 中配置
}

enum MemberRole {
  owner
  admin
  member
}

enum MemberStatus {
  active
  disabled
  removed
}

model User {
  id               String    @id @default(cuid())
  email            String    @unique
  passwordHash     String    @map("password_hash") @db.VarChar(100)
  nickname         String    @db.VarChar(50)
  avatarUrl        String?   @map("avatar_url") @db.VarChar(500)
  emailVerifiedAt  DateTime? @map("email_verified_at")
  lastLoginAt      DateTime? @map("last_login_at")
  status           UserStatus @default(active)
  createdAt        DateTime  @default(now()) @map("created_at")
  updatedAt        DateTime  @updatedAt @map("updated_at")

  memberships Membership[]
  @@map("users")
}

model Tenant {
  id         String   @id @default(cuid())
  name       String   @db.VarChar(100)
  logoUrl    String?  @map("logo_url") @db.VarChar(500)
  brandColor String?  @map("brand_color") @db.VarChar(9)
  ownerId    String   @map("owner_id")
  deletedAt  DateTime? @map("deleted_at")
  createdAt  DateTime @default(now()) @map("created_at")
  updatedAt  DateTime @updatedAt @map("updated_at")

  owner      User         @relation("TenantOwner", fields: [ownerId], references: [id])
  memberships Membership[]
  @@index([ownerId])
  @@map("tenants")
}

model Membership {
  id            String       @id @default(cuid())
  tenantId      String       @map("tenant_id")
  userId        String       @map("user_id")
  role          MemberRole   @default(member)
  status        MemberStatus @default(active)
  invitedBy     String?      @map("invited_by")
  joinedAt      DateTime     @default(now()) @map("joined_at")
  lastActiveAt  DateTime?    @map("last_active_at")
  createdAt     DateTime     @default(now()) @map("created_at")
  updatedAt     DateTime     @updatedAt @map("updated_at")

  tenant Tenant @relation(fields: [tenantId], references: [id], onDelete: Cascade)
  user   User   @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([tenantId, userId])
  @@index([userId])
  @@map("memberships")
}
```

**全库建模纪律**（对应数据字典 §1）：

1. 表名复数 snake_case，字段 snake_case → Prisma model 用 PascalCase + `@map`/`@@map`
2. 除 `users` / `plans` / `payment_idempotency` / `refresh_tokens` / `email_tokens` 外，**所有表强制含 `tenant_id` + 索引**
3. 金额一律 `*_cents Int`，**全链路无浮点**
4. 时间戳 `TIMESTAMP(3) UTC`，`created_at`/`updated_at` 必备
5. 外键明确 `onDelete`：跨域**不级联**，防误删扩散
6. 枚举取 PG 原生 ENUM，取值与 shared 包常量同源

### 3.5 pgvector（AI 域，M4 用到，先建好）

Prisma 不支持 vector 类型 → `Unsupported("vector(1536)")` + 手写 migration SQL：

```prisma
model AiChunk {
  id         String   @id @default(cuid())
  tenantId   String   @map("tenant_id")
  documentId String   @map("document_id")
  seq        Int
  content    String
  embedding  Unsupported("vector(1536)")?
  tokenCount Int      @map("token_count")
  createdAt  DateTime @default(now()) @map("created_at")

  document AiDocument @relation(fields: [documentId], references: [id], onDelete: Cascade)
  @@index([tenantId, documentId])
  @@map("ai_chunks")

```

首次 migration 后，手工在生成的 `migration.sql` 中追加：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE INDEX idx_ai_chunks_embedding ON ai_chunks
  USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);
```

### 4.2 后端消费（NestJS 12 Standard Schema）

```ts
import { Body, Controller, Post } from '@nestjs/common';
import { registerSchema, type RegisterInput } from '@saas/shared';

@Controller('auth')

>
> **状态码说明（实测 `StandardSchemaValidationPipeOptions`）**：该管道的 `errorHttpStatusCode` **默认是 `HttpStatus.BAD_REQUEST`（400）**，不是 422。若 TSD/测试计划要求 422，需显式配置：
>
> ```ts

>   new StandardSchemaValidationPipe({ errorHttpStatusCode: HttpStatus.UNPROCESSABLE_ENTITY }),

> ```
>
> **建议**：保持 NestJS 默认 **400**，并在 `packages/shared/src/errors.ts` 的错误码表里把校验失败码固定为 `VALIDATION_FAILED`；前端 Axios 拦截器按错误码而非状态码分支，状态码变动不会引发前端回归。

### 4.4 Swagger 接入 Zod（必须做，否则 /docs 里没有请求体结构）

**Zod 4 内置 JSON Schema 转换器，不需要额外依赖。** 实测 `zod@4.6.7` 顶层导出 `toJSONSchema`，且 `target` 支持 `"openapi-3.0"`（Zod 4 `ToJSONSchemaParams.target` 实测取值：`"draft-04" | "draft-07" | "draft-2020-12" | "openapi-3.0"`）。

`apps/api/src/common/swagger.ts`：

```ts
import { SwaggerModule } from '@nestjs/swagger';
import { z } from 'zod';
import type { ZodType } from 'zod';

function isZodSchema(schema: unknown): schema is ZodType {
  return !!schema && typeof schema === 'object' &&
    (schema as { '~standard'?: { vendor?: string } })['~standard']?.vendor === 'zod';
}

export const standardSchemaConverter = (
  schema: unknown,
  { schemaType }: { schemaType: 'input' | 'output' },
) => {
  if (!isZodSchema(schema)) return undefined;
  return {
    schema: z.toJSONSchema(schema, {
      target: 'openapi-3.0',
      io: schemaType,
      unrepresentable: 'any',   // z.date() / z.bigint() 等无法表示的类型降级为 {}
    }),
  };
};

// 在 main.ts 中：
const doc = SwaggerModule.createDocument(app, config, { standardSchemaConverter });
```

> **不引入 `zod-openapi` 的理由**：Zod 4 已自带 `toJSONSchema` 且原生支持 `openapi-3.0` 目标，多引一个包就多一处版本对齐负担（该包当前 6.0.2）。
> **备选**：装 `@cafercangundogdu/nestjs-zod-openapi@0.2.0`（peer 支持 nest 11/12 + swagger 11/12 + zod 4），用其 `patchNestSwagger()` 一行接入，自带 `.openapi('Name')` 命名 schema → 组件化 `$ref` 优于上面的内联。**注意不要用 `nestjs-zod@5.5.0`，其 peer 是 `@nestjs/common ^10||^11`，不兼容 Nest 12。**
> **校验规则的落库**：Zod 4 的 `z.email()` 等顶层 API 会被转成 OpenAPI 的 `format: "email"` + `type: "string"`，但**自定义的业务约束（如 `password` 最长 72 字节）在 JSON Schema 里只能体现为 `maxLength`**。若某条约束对前端重要，改为在 `packages/shared` 的 schema 上用 `.describe('...')` 补充说明。

```ts
// common/guards/jwt-auth.guard.ts —— 全局守卫，@Public() 放行公开路由
@Injectable()
export class JwtAuthGuard implements CanActivate {
  constructor(
    private readonly reflector: Reflector,
    private readonly tokenService: TokenService,
  ) {}

  async canActivate(ctx: ExecutionContext) {
    const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [ctx.getHandler(), ctx.getClass()]);
    if (isPublic) return true;

    const req = ctx.switchToHttp().getRequest<Request>();
    const token = extractBearer(req.headers.authorization);
    if (!token) throw new UnauthorizedException({ code: 'UNAUTHORIZED', message: '缺少访问令牌' });

    try {
      const payload = await this.tokenService.verifyAccess(token);
      req.user = { userId: payload.sub, tenantId: payload.tenantId };
      return true;
    } catch (e) {
      throw new UnauthorizedException({ code: 'TOKEN_EXPIRED', message: '访问令牌已过期或无效' });
    }
  }
}
```

```ts
// common/guards/tenant.guard.ts —— 校验 X-Tenant-Id 对应 membership 存在且 active
@Injectable()
export class TenantGuard implements CanActivate {
  async canActivate(ctx: ExecutionContext) {
    const req = ctx.switchToHttp().getRequest<Request>();
    const tenantId = req.headers['x-tenant-id'];
    if (typeof tenantId !== 'string' || !tenantId) {
      throw new ForbiddenException({ code: 'TENANT_MISMATCH', message: '缺少租户上下文' });
    }
    const membership = await this.membersService.findActive(req.user.userId, tenantId);
    if (!membership) {
      throw new ForbiddenException({ code: 'TENANT_MISMATCH', message: '无权访问该租户' });
    }
    req.tenantId = tenantId;
    req.userRole = membership.role;
    return true;
  }
}
```

**业务纪律**：**任何 Controller 都不从参数读 tenantId**，只从 `req.tenantId` 取；`X-Tenant-Id` 头由前端 Axios 拦截器自动注入（TSD §4.5）。

### 5.2 多租户行级隔离（TSD §5.4，Prisma 7 版）

> ⚠️ **知识点 M2-03 的伪代码 `prisma.$use()` 在 Prisma 7 已移除**，落地必须用 Client Extension。

`apps/api/src/prisma/tenant.extension.ts`：

```ts
import { AsyncLocalStorage } from 'node:async_hooks';
import { Prisma } from '../generated/prisma/client.js';

// 请求级租户上下文
export const tenantContext = new AsyncLocalStorage<{ tenantId: string }>();

const TENANT_SCOPED = new Set([
  'Resource', 'File', 'AiDocument', 'AiChunk', 'AiConversation', 'AiMessage',
  'Subscription', 'SubscriptionEvent', 'Invoice', 'GatewayTransaction',
  'Notification', 'NotificationPreference', 'AuditLog', 'UsageMonthly',
  'Membership', 'Invitation',
]);

export function tenantScopedExtension() {
  return Prisma.defineExtension({
    name: 'tenant-scope',
    query: {
      $allModels: {
        async $allOperations({ model, operation, args, query }) {
          const ctx = tenantContext.getStore();
          if (!ctx || !TENANT_SCOPED.has(model ?? '')) return query(args);

          const where = (args.where ?? {}) as Record<string, unknown>;
          const extra =
            operation === 'create'
              ? { data: { ...(args.data as object), tenantId: ctx.tenantId } }
              : { where: { ...where, tenantId: ctx.tenantId } };

          return query({ ...args, ...extra } as typeof args);
        },
      },
    },
  });
}
```

`PrismaService` 装配扩展：

```ts
super({ adapter: ... });
// 构造后：
return this.$extends(tenantScopedExtension());
```

（`PrismaService extends PrismaClient` 的写法需调整——扩展后的 client 类型不同，建议改为组合：内部持有 `PrismaClient` 实例，或用 `Prisma.defineExtension((client) => client.$extends(...))` 的闭包形式。）

**中间件建立上下文**（`common/middleware/tenant-context.middleware.ts`）：

```ts
export function tenantContextMiddleware(req: Request, res: Response, next: NextFunction) {
  const tenantId = req.headers['x-tenant-id'];

    tenantContext.run({ tenantId }, () => next());

    next();
  }
}
```

> **隔离三道防线**（缺一不可）：
> 1. TenantGuard 校验 membership（防越权进入）
> 2. Prisma Extension 自动合并 `tenantId`（防漏写过滤）— **第二道防线，代码纪律失效时的兜底**

### 5.3 RBAC（TSD §5.5）

```ts
// common/guards/roles.guard.ts
@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(ctx: ExecutionContext) {
    const required = this.reflector.getAllAndOverride<MemberRole[]>(ROLES_KEY, [ctx.getHandler(), ctx.getClass()]);
    if (!required?.length) return true;
    const role = ctx.switchToHttp().getRequest<Request>().userRole;
    if (!required.includes(role)) {
      throw new ForbiddenException({ code: 'ROLE_DENIED', message: '当前角色无权执行该操作' });
    }
    return true;
  }
}
```

**权限矩阵（与 TSD §4.6 同源，常量放 shared 包）**：

| 操作 | member | admin | owner |
|------|--------|-------|-------|
| 资源增删改 / 上传附件 | ✅ | ✅ | ✅ |
| 回收站管理 / 审计查看 | ❌ | ✅ | ✅ |
| 邀请 / 调角色 / 禁用 / 移除 | ❌ | ✅（admin 不能改 owner） | ✅ |
| owner 转让 | ❌ | ❌ | ✅ |
| 订阅 / 退款 / 账单 | ❌ | ❌ | ✅ |
| 租户设置 | ❌ | ✅ | ✅ |

**边界规则**：admin 可管理 member、不可改动 owner、不可自降级（防租户无主）；owner 转让需目标为 active 成员，事务内角色互换 + 审计。
