## 1. 手册目标与使用方式

本文档是**可直接照做的操作手册**，覆盖从「申请资源」到「线上可访问」的完整链路，面向**没有运维经验的前端开发者**（知识点 M6-01 §2）。

使用方式：
- 首次搭建：按 §3 → §4 顺序执行，每步有验收命令
- 日常发版：§6（CI/CD）+ §7（迁移纪律）
- 出故障：§10（排错手册）按症状查表

> **重要边界**：本文档中所有**服务价格档位、平台界面、配置项名称**均可能随平台调整而失效。执行前以平台官方最新文档为准，命令以本地实测为准。

## 2. 架构与部署拓扑速览

```
用户浏览器
   │  https://app.silencewood.cn
   ▼
Cloudflare（DNS + CDN + Universal SSL）
   ├── CNAME → Cloudflare Pages（前端静态，apps/web/dist）
   └── CNAME → Render（后端常驻进程，apps/api，api.silencewood.cn）
                    │
                    ├──→ Neon（PostgreSQL 17 + pgvector）
                    ├──→ Upstash Redis（BullMQ 队列 + 缓存）
                    ├──→ 腾讯云 COS（文件对象存储，S3 兼容）
                    ├──→ Resend（邮件 · HTTPS API，端口 443）
                    └──→ OpenAI 兼容 LLM API（Embedding + 对话）

CI：GitHub Actions（push main → lint/test/build → migrate → deploy）
```

|----|---------|------|-------|
| 前端 | Cloudflare Pages | 免费 | ✅ |

### 3.3 申请时的四个坑

- **Neon 空闲 5 分钟挂起不可关**（Free 档）：每次唤醒有几百毫秒延迟，且**挂起期间仍计存储费**。演示场景可接受；生产可升 Launch 档关闭 scale-to-zero。
- **Resend 免费档每天限 100 封**：不是 3000 封/月就完事——**日限是硬上限**，演示时批量验证邮件会撞墙。撞墙后改用本地 SMTP 捕获模式验证。
- **Render 免费档屏蔽出站 SMTP 25/465/587**（2025-09-26 起）：这是**本项目邮件方案的硬约束**，详见 §6.6。切勿用 nodemailer 直连 SMTP。
- **OpenAI 预付费制**：不充值不能调 API；API 计费与 ChatGPT 订阅完全独立。务必在 Billing 设置**月度消费上限**——key 泄露时这是唯一止损线。

## 6. 部署配置：分平台操作

### 6.1 Cloudflare Pages（前端）

1. Dashboard → **Workers & Pages** → Create → Pages → **Connect to Git**
2. 选仓库 `silent-wood/saas-starter`，分支选 `main`
3. 构建配置：
   | 项 | 值 |
   |----|-----|
   | Framework preset | None（Vite 自识别） |
   | Build command | `pnpm --filter web build` |
   | Build output directory | `apps/web/dist` |
   | Root directory | 仓库根（不要填 `apps/web`，否则找不到 workspace） |
4. **环境变量**（Settings → Environment variables → Production）：
   - `VITE_API_BASE_URL` = `https://api.silencewood.cn/api/v1`
   - `NODE_VERSION` = `22`（指定 pnpm 找不到时加 `COREPACK_ENABLE_STRICT=0`）
5. 自定义域名：Pages → Custom domains → 添加 `app.silencewood.cn`
6. **Vite history 模式 fallback**：`apps/web/public/_redirects` 写入 `/* /index.html 200`（或 Pages 设置里加 rewrite 规则），否则刷新子路由 404

> **根目录坑**：Monorepo 下 Root directory 留空 + Build output 填 `apps/web/dist` 最稳；填 `apps/web` 会导致 pnpm 找不到根 workspace。

### 6.2 Render（后端）

1. Dashboard → **New → Web Service** → Connect repo
2. 配置：
   | 项 | 值 |
   |----|-----|
   | Root Directory | 仓库根 |
   | Build Command | `pnpm install --frozen-lockfile && pnpm --filter api build` |
   | Start Command | `pnpm --filter api exec prisma migrate deploy && node apps/api/dist/main.js` |
   | Node 版本 | 22（环境变量 `NODE_VERSION`） |
3. **Environment** 填入 §4.1 全部变量（**用 Render 的 Secret/Env，而非代码库**）
4. 实例类型：免费档（休眠）/ 常驻（¥70–140/月，演示建议常驻避免冷启动）
5. 自定义域名：Settings → Custom Domains → `api.silencewood.cn`
6. Health Check Path：`/health`

> **启动命令顺序不可颠倒**：`migrate deploy` 必须在 `node main.js` 之前（知识点 M6-01 §6）。结构没迁移就起新代码 → 接口 500。

**免费档限制（必须知情）**：

| 限制 | 影响 | 应对 |
|------|------|------|
| 512MB RAM / 0.1 CPU | 跑得起 NestJS，但并发低 | 演示级足够；Worker 与 API 同进程（TSD §5.8） |
| 15 分钟无请求自动休眠，冷启动约 1 分钟 | 演示首屏等待久，期间访问返回加载页 | 保活（§9.2）或用 Starter 常驻实例 |
| 每月 750 实例小时 / 工作区 | 单服务独占 | 只有一个后端服务，够用 |
| **出站 SMTP 25/465/587 封锁** | **nodemailer 直连 SMTP 不可用** | 邮件改走 Resend HTTPS API（§6.6） |
| 本地文件系统临时（ephemeral） | 重启/休眠后本地文件丢失 | 文件走 COS、数据走 Neon，**不在本地磁盘存状态** |
| 免费 Postgres 30 天后删除 | —— | 本项目用 Neon，不受影响 |
| 不支持持久磁盘 / SSH / 平台 cron | 定时任务无处安放 | BullMQ repeatable job 在应用启动时注册，不依赖平台 cron |

### 6.3 Neon（数据库）

#### 6.3.0 建项目：入口与逐项选择（2026-10 复核，必读）

> **先看这一条**：如果建项目时报 `action restricted; reason: "organization is managed by Vercel"`，**直接跳到 §6.3.0.2**——那不是权限 bug，是当前所在的组织由 Vercel 托管，控制台禁止在其中建项目。

Neon 控制台新建 Project 页面现提示「要创建新项目，请使用 Vercel 中的 Neon Postgres 集成」，即**控制台不再作为默认建项目入口**。这不是账号注册失败，绕过方式有两条：

**路径 A（推荐，本项目采用）：用 Neon CLI 建项目**

CLI 走 Neon API，完全绕开控制台 UI，**也不引入 Vercel 依赖**（本项目后端部署在 Render，不在 Vercel）：

```bash
# 1. 安装（npm 包已更名为 neon，neonctl 是它的别名；brew 公式名仍为 neonctl）
npm i -g neon           # 需要 Node ≥ 20.19.0
neon --version

# 2. 鉴权：浏览器授权（命令为 neon login，auth 为旧名）
neon login              # 打开浏览器完成授权，凭据写入 ~/.config/neon/credentials.json

# 3. 建项目（region 见下方可选值，Singapore = aws-ap-southeast-1）
neon projects create --name saas-starter --region-id aws-ap-southeast-1 --pg-version 17

# 4. 取连接串（也可在控制台 Connect 面板复制）
neon connection-string --pooled     # 池化地址 → DATABASE_URL
neon connection-string              # 直连地址 → DIRECT_DATABASE_URL
```

> **若 `neon login` 不可用**：说明账号是经 Vercel 集成创建的（Vercel 托管账号的 `neon login` 浏览器授权官方明确不支持）。改用 API key：控制台 → 右上角用户菜单 → **Account settings → API keys → Create new API key**（token 只显示一次，当场存进 Secrets）→ `export NEON_API_KEY=...`，再执行建项目命令。personal API key 属**账号级**，可访问你作为成员的所有组织的项目，跨组织通用。
>
> **Vercel 托管组织内建项目仍会被拦**（报 `organization is managed by Vercel`），此时必须指定个人组织的 `--org-id`——见 §6.3.0.2。

**路径 B：按提示走 Vercel 集成**

Marketplace → Neon Postgres → Install → 选 region 与 plan → 命名数据库。代价是**数据库的 plan 变更、成员管理、配置改到 Vercel 后台**，且数据库**不能转移到其他 Neon 组织**（官方明确：Vercel 托管组织不支持项目转移）。本项目刻意拆多平台以展示部署运维能力（TSD 附录 A.7），不建议。

#### 6.3.0.2 报错 `organization is managed by Vercel` 的处理

点 Create 报 `action restricted; reason: "organization is managed by Vercel"`：**不是权限 bug**。当前所在组织是经 **Vercel Marketplace 集成**创建的（组织名形如 `Vercel: <team>`），这类 Vercel 托管组织禁止在其中建项目，也**不能作为项目转移的目标**。三条出路：

| 路径 | 操作 | 适用 |
|---|---|---|
| **A. 切到个人组织**（推荐） | 控制台**左上角组织切换下拉** → 选个人组织 → 回到 Create project 重新建 | 想继续走控制台界面 |
| **B. CLI 指定个人组织** | `neon orgs list` 查个人组织的 org_id（标 `[current]` 的是当前上下文）→ 建项目命令加 `--org-id <org_id>` | 想走 CLI；个人 API key 是账户级、跨组织通用（§6.3.0），无需单独建组织 key |
| **C. 卸载 Vercel 集成** | Vercel 控制台 → Settings → Integrations → Neon Postgres → Uninstall | 确认不再需要 Vercel 托管的数据库时才用；**会删除整个托管组织** |

#### 6.3.1 建库后的配置步骤

1. 获取连接串：项目 Dashboard → **Connect** 按钮（或左侧导航 Connect）→ 打开 Connect 弹窗 → 选 branch / compute / database / role → 复制
   - **连接池开关就在这个弹窗里**（Connection pooling toggle，2026-10 官方文档口径）：**新项目默认开启**——开 = 显示池化地址（host 带 `-pooler`），关 = 显示直连地址
   - 该开关**只切换显示哪条串，不启停池化**：池化端点始终存在、始终可用，应用侧用哪条串才是真正的「开关」
   - 池化地址：`postgresql://USER:PASS@ep-xxx-pooler.aws-ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require`
   - 直连地址：`postgresql://USER:PASS@ep-xxx.aws-ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require`
   - CLI 等价：`neon connection-string --pooled`（池化）/ `neon connection-string`（直连）
2. **两条串各用在哪**（池化 = PgBouncer transaction 模式，单个池化端点最高 10,000 客户端连接；池化不支持 SQL 级 prepared statement、`SET` 会话变量、`LISTEN/NOTIFY`，这类操作一律走直连）：
   - `DATABASE_URL` = 池化地址（运行时）
   - `DIRECT_DATABASE_URL` = 直连地址（Prisma Migrate 用，**池化地址不支持迁移**，会报 `prepared statement "s0" already exists`）
3. 启用 pgvector：左侧导航栏 → 展开 **Postgres database** 折叠组 → **SQL Editor**（2026-08 控制台改版后 SQL Editor 收进了这个折叠组，不再是侧栏一级入口；也可用本地 psql 执行），运行 `CREATE EXTENSION IF NOT EXISTS vector;`
   - **pgvector 全档位可用，无需附加付费**；扩展按 database 安装而非按 project——同 branch 下多 database 需各自执行一次
   - 验证：`SELECT extname, extversion FROM pg_extension WHERE extname = 'vector';`
4. 备份：每日自动备份 + **Time Travel（时间点恢复）** + branch 分支功能，可在迁移前建分支做快照演练
5. **Free 档注意**：空闲 5 分钟自动挂起且**不可关闭**，唤醒有几百毫秒延迟，挂起期间仍计存储费

> **连接串参数说明**：`sslmode=require` 与 `channel_binding=require` 是 Neon 现行连接串的标配（SCRAM-SHA-256-PLUS 双向认证），不要手动删。Prisma 的 quaint 驱动能识别 `channel_binding`，不会报错；仅当改用 `@prisma/adapter-neon` 的 HTTP 适配器时才需剥离该参数——本项目后端跑 Render，用 `@prisma/adapter-pg`（TCP），不受影响。

### 6.5 腾讯云 COS（文件存储）

> **选型变更（2026-10-28）**：原计划用 Cloudflare R2，但 R2 激活必须绑 Visa/Mastercard/AmEx 等外币卡（纯银联单币卡无法通过），而本项目用户/面试官均在国内、演示级低流量，**改用腾讯云 COS**——支付宝/微信即可开通、零绑卡门槛、国内直连更快、免费额度更充裕（50GB 存储 + 10GB 流量/月）。后端保持 **S3 兼容接入**（`@aws-sdk/client-s3`），代码层仅 endpoint/region/key 配置不同，改动极小。

1. 开通：腾讯云控制台 → **对象存储 COS** → 开通服务（免费自动发放 50GB 存储 + 10GB 下行流量 + 100 万读/10 万写请求 免费额度，演示级约 ¥0/月）
2. **创建存储桶**：名称 `saas-starter-<APPID>`（全局唯一，系统自动追加账号 APPID）→ 地域 **广州 ap-guangzhou**（国内访问近）→ 访问权限 **私有读写**（上传/下载走预签名 URL，不要公开）
3. 密钥：控制台 → **访问管理 → API 密钥 → 新建密钥** → 得到 `SecretId` / `SecretKey`（**只显示一次，立即存进 Render Secrets 与 GitHub Secrets**）
4. 接入（**S3 兼容**，与 R2 同套后端代码）：
   - `COS_ACCESS_KEY_ID` = SecretId
   - `COS_SECRET_ACCESS_KEY` = SecretKey
   - `COS_ENDPOINT` = `cos.ap-guangzhou.myqcloud.com`
   - `COS_REGION` = `ap-guangzhou`
   - `COS_BUCKET` = `saas-starter-<APPID>`
5. 公开访问（演示级）：桶创建后自动分配公网域名 `https://<bucket>.cos.ap-guangzhou.myqcloud.com`，**立即可用且无需 ICP 备案**；绑 `files.silencewood.cn` 自定义域名需备案，演示期不做
   - 生产应改用**签名 URL 短期有效**（预签名 PUT 上传 + 签名 GET 下载），本项目预签名已实现（COS 的 `getPresignedUrl` 或 S3 协议的 `sign`）

### 6.6 邮件（Resend · HTTPS API）

> **为什么不用 SMTP**：Render 免费 Web Service 自 2025-09-26 起**封锁出站 25/465/587 端口**，nodemailer 直连 SMTP 会静默超时（本地正常、线上必挂，是典型的高耗时坑）。改用 Resend **HTTPS API**（走 443 端口，任何托管平台都不封），是各大云平台官方推荐做法。

1. https://resend.com/signup 注册 → **API Keys** → Create API Key → 复制 `re_xxx`（**只显示一次**）
2. **Domains** → Add Domain → 填 `silencewood.cn` → 按提示在 Cloudflare 加 DNS 记录（SPF / DKIM / DMAME，Resend 会给出具体值）→ 等验证通过
   - 未验证域名只能用 Resend 沙箱模式（**仅能发给自己**），无法给真实用户发信
3. `MAIL_API_KEY` / `MAIL_FROM` 写入 Render 环境变量
4. 发送实现：`EmailService` 用 **策略模式**封装，`MAIL_PROVIDER` 决定实现：
   - `resend` → HTTPS API（生产）
   - `smtp` → nodemailer（**仅本地**，依赖本机不封端口）
   - `mock` → 捕获到内存（**仅测试**，测试断言「发了什么」而非真发）

5. **免费额度**：3000 封/月 且 **100 封/天**（日限是硬上限）。演示批量验证时撞日限，改用 `mock` provider 在测试环境验证流程。

### 6.7 DNS 与 SSL（Cloudflare）

```
1. Cloudflare → Add Site → 填 silencewood.cn → 选 Free 套餐
2. 按提示把域名 NS 改到 Cloudflare 给出的两条 Nameserver（去域名注册商后台改）
3. 等 NS 生效（通常 30 分钟–24 小时）
4. DNS 记录：
   app  → CNAME → <project>.pages.dev        （Proxied：橙云）
   api  → CNAME → <service>.onrender.com     （Proxied：橙云）
5. SSL/TLS → Overview → Universal SSL（自动签发，免费）
6. Edge Certificates → Always Use HTTPS：On
```

> **改 DNS 前先把 TTL 调到 60 秒**，生效后再调回 3600（知识点 M6-01 §6：DNS 缓存导致解析迟迟不生效）。
> **迁移 ≠ 清空**：本域名可能还有其他仓库在用的解析记录（如 GitHub Pages 的 `185.199.x.x` A 记录、其他托管平台的 CNAME）。切 NS 前必须：① 在 DNSPod 导出/截图**全部现有记录**；② 在 Cloudflare **逐条重建**（Add Site 的自动扫描会漏，以 DNSPod 列表为准逐一核对）；③ 两边记录完全一致后，才去注册商改 NS。NS 切换后最长 24–48 小时内新旧两家 DNS 会被随机访问（双写期），期间两边都必须保有完整一致的记录，否则其他仓库的站点会间歇性失联。
> **橙云规则分两类**：本项目 `app` / `api` **橙云必须开**（灰云会让 Render 证书与 Pages 域名校验异常）；**其他仓库的 GitHub Pages / Vercel 等自定义域名记录保持灰云（DNS only）**——橙云代理会干扰 GitHub Pages 的证书签发与 Enforce HTTPS 续期。

### 6.8 免备案说明

前端（Cloudflare）、后端（Render）、数据库（Neon）**全部在境外**，域名无需 ICP 备案。若未来迁回国内服务器，需补备案（周期 1–2 周）——这个决策已固化在需求文档第 2 章，不在 v1 范围。

## 7. CI/CD 流水线

### 7.1 三条 workflow

| 文件 | 触发 | 职责 |
|------|------|------|
| `.github/workflows/ci.yml` | PR + push 任意分支 | lint → tsc → test（单测+e2e）→ build（**质量门禁，不部署**） |
| `.github/workflows/deploy-web.yml` | push main | 构建前端 → 部署 Cloudflare Pages |
| `.github/workflows/deploy-api.yml` | push main | 构建后端 → `prisma migrate deploy` → 部署 Render |

### 7.2 CI 关键配置

```yaml
# .github/workflows/ci.yml（要点）
name: CI
on:
  pull_request: { branches: [main, dev] }
  push: { branches: [main, dev] }
jobs:
  quality:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: pgvector/pgvector:pg16      # 带 pgvector 的测试库
        env: { POSTGRES_PASSWORD: test }
        options: >-
          --health-cmd pg_isready
          --health-interval 10s --health-timeout 5s --health-retries 5
        ports: ['5432:5432']
    env:
      DATABASE_URL_TEST: postgresql://postgres:test@localhost:5432/saas_test
      DATABASE_URL: ${{ secrets.DATABASE_URL_TEST }}   # 供 Prisma client 使用
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with: { version: 11 }
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: pnpm }
      - run: pnpm install --frozen-lockfile
      - run: pnpm turbo run lint
      - run: pnpm turbo run typecheck
      - run: pnpm turbo run test        # 含 e2e（连 services 的 postgres）
      - run: pnpm turbo run build
```

**要点**：
- 测试库用 `pgvector/pgvector:pg16` 官方镜像 → CI 不用连 Neon，**测试不依赖外部服务**（知识点 C-01 §6）
- `pnpm install --frozen-lockfile` → 保证 CI 用的是 lockfile 版本，不被本地随意改动
- 缓存：`actions/setup-node` 的 `cache: pnpm` + Turborepo 缓存（`turbo.json` 声明 `outputs`）

### 7.3 部署 workflow 要点

| 项 | 说明 |
|----|------|
| 触发条件 | `push` 到 `main`（或 GitHub Release tag） |
| 依赖 | `deploy-api` 与 `deploy-web` 各自独立，web 失败不阻塞 api（或反之，按需 needs） |
| Secrets | `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_API_TOKEN` / `RENDER_API_KEY` / `RENDER_SERVICE_ID` 存仓库 Secrets |
| 迁移执行 | 在 `deploy-api` 中、部署**之前**执行 `prisma migrate deploy`（连生产 `DATABASE_URL`） |
| 产物 | Turborepo 缓存命中时秒级完成；`turbo run build --filter=...` 只构建受影响包 |

### 7.4 门禁验证（自测，知识点 M6-02 §7）

- [ ] PR 触发 CI，四段全绿才允许合并
- [ ] 故意提交一个失败测试 → CI 红 → 合并被 GitHub 分支保护拦住
- [ ] push main → 前端 Pages 自动更新（分钟级）
- [ ] push main → 后端 Render 自动部署，**日志中可见 migrate deploy 输出**
- [ ] 仓库 Secrets 在 CI 日志中显示为 `***`（GitHub 自动遮蔽），代码与日志均无明文

## 8. 数据库迁移纪律

| 场景 | 命令 | 规则 |
|------|------|------|
| 本地开发 | `prisma migrate dev` | 会重置库，仅本地可用，**生产禁用** |
| CI / 生产部署 | `prisma migrate deploy` | 只应用未执行的迁移，绝不重置 |
| 查看状态 | `prisma migrate status` | 部署前确认无 pending |

**铁律**（知识点 M2-04 §6）：
1. 已应用到生产的 migration **文件永不修改**，有变更就新增一个 migration（补偿）
2. 生产**绝不用** `migrate dev` / `db push`（`db push` 会直接改结构且不留记录，团队协作禁用）
3. 涉及删列/改名的迁移，先做「双写 → 迁移 → 清理」三步，避免旧代码在灰度期间报错
4. 大表加索引用 `CREATE INDEX CONCURRENTLY`（避免锁表），需手写 SQL 迁移
5. 部署前若不确定，先在 Neon 建 **branch 分支** 做快照演练

- 免费档休眠后首次请求冷启动 30–60 秒 → 对演示体验伤害大
- 方案 A（推荐，演示前）：手动切常驻实例（¥70–140/月，需求文档预算 < ¥100/月内）
- 方案 B（免费）：外部 cron 每 10 分钟探活，但首次请求仍会慢
- 方案 C：Cloudflare Workers 定时任务探活（免费额度内）

### 9.3 回滚

| 层级 | 操作 | 耗时 |
|------|------|------|
| 前端 | Pages → Deployments → 选旧版本 → 重新部署（秒级） | < 1 分钟 |
| 后端 | Render → 该服务 → Rollback to previous deploy | < 2 分钟 |
| 数据库 | **迁移不可自动回滚** → 用 Neon 分支/时间点恢复（PITR） | 视数据量 |

> ⚠️ 迁移导致的故障，**优先做前向修复**（新增补偿 migration），不要回滚数据库——回滚代码但数据库已变更会造成结构不一致。

## 10. 排错手册

### 10.1 排错顺序（知识点 C-03 §4）

```
① 看平台日志（Render 日志 / Pages 构建日志）
② 查迁移是否执行（psql \dt 看表结构是否最新）
③ 核 Secrets 是否配对（变量名拼写、是否漏配）
④ 查 CORS / 限流 / 域名解析
⑤ 查数据库连接（池化地址 vs 直连地址用错是高频坑）
```

### 10.2 症状速查表

| 症状 | 最可能原因 | 处理 |
|------|-----------|------|
| 前端打开白屏 | JS 加载失败 / base path 错 | 看浏览器 Console 404；查 Pages 构建产物目录是否 `apps/web/dist` |
| 前端 404（刷新子路由） | history fallback 未配 | 加 `public/_redirects`：`/* /index.html 200` |
| 接口全部 CORS 报错 | `CORS_ORIGINS` 未含前端域名 / 多了斜杠 | 核对环境变量，值必须精确等于 `https://app.silencewood.cn`（无尾部斜杠） |
| 登录后立刻 401 | access 过期或 `JWT_SECRET` 变了 | 查时钟漂移；确认环境变量在 Render 已配置（不同环境不同 secret 会导致 token 无效） |
| 部署后接口 500 且提示字段不存在 | 迁移没跑 | Render 日志确认 `migrate deploy` 执行；手动补跑 |
| 数据库连接超时 | 用错连接串类型 | 运行时用池化地址，迁移用直连地址；确认 `sslmode=require` |
| 队列任务不执行 | Upstash 连接参数 / 免费额度 | BullMQ 需 `maxRetriesPerRequest: null`；查 Upstash 用量 |
| 邮件发不出去 | ① Render 免费档封了 SMTP 端口（用 HTTPS API 绕开）② 域名未验证 ③ 撞 Resend 日限 100 封 | 查 `MAIL_PROVIDER` 是否为 resend；查 Resend 域名验证状态；查 `MAIL_FROM` 是否为已验证域名；超日限则用 mock provider |
| 邮件一直超时（ETIMEDOUT / ENETUNREACH） | 本地能发线上不能发 → **典型 SMTP 端口被封** | 不是代码问题。改用 HTTPS API（Resend SDK），或升级 Render 实例 |
| SSE 连上就断 | 平台代理超时 | 加心跳 30s + `X-Accel-Buffering: no` 响应头 |
| COS 上传 403 | 密钥权限或过期 | 访问管理 → API 密钥 重新生成 SecretId/SecretKey；确认 Bucket 名与 region |
| AI 提问 500 | embedding 模型维度不匹配 | 确认 1536 维模型；查 `ai_chunks.embedding` 维度 |
| 部署变慢 | Turborepo 缓存失效 | 检查 `turbo.json` 的 `inputs` 是否包含 env 文件；必要时 `--force` |
| 首次请求慢 30s | Render 免费档冷启动 | 保活（§9.2）或用常驻实例 |

### 10.3 日志规范（C-03 §3）

- **结构化 JSON**：`{ ts, level, msg, traceId, tenantId, userId, path, status, durationMs }`
- **级别策略**：生产 `info` 起，异常 `error`（必带 tenantId/操作名/错误码）；`debug` 仅本地开
- **脱敏**：密码、token、密钥、完整邮箱手机号一律 MASK（审计表与日志同等对待）
- **traceId**：入口中间件生成（`X-Request-Id` 透传），串起一次请求的前后端与异步任务
- **禁止**：打印完整请求体、LLM 全文提示词中的用户隐私内容

## 11. 密钥管理与轮换

| 密钥 | 存放位置 | 轮换频率 | 泄露处置 |
|------|---------|---------|---------|
| `JWT_SECRET` | Render Secret | 90 天 | 立即更换 → **所有会话失效，用户需重新登录**（预期行为） |
| `DATABASE_URL` | Render Secret | 按需 | 更换后重启实例 |
| `COS_ACCESS_KEY_ID` / `COS_SECRET_ACCESS_KEY` | Render Secret / GitHub Secrets | 90 天 | 访问管理 → API 密钥 撤销旧密钥 → 重新生成 → 更新两处 |
| `SMTP_PASS` | Render Secret | 90 天 | 服务端重置（仅本地用，不入生产） |
| `MAIL_API_KEY` | Render Secret | 90 天 | Resend 后台撤销并新建 |
| `LLM_API_KEY` | Render Secret | 90 天 | 服务端撤销并新建 |
| CI Secrets | GitHub Secrets | 90 天 | 仓库 Settings → Secrets |
| 域名 DNS | Cloudflare | — | 开启 2FA + 登录保护 |

**防呆机制**：
1. `.gitignore` 强制忽略 `.env*`（保留 `.env.example`）
2. pre-commit 钩子扫描 `git diff --cached` 中的密钥特征（`sk-`、`re_`、`AKIA`、长 base64）
3. CI 中 `git-secrets` 扫描全量历史（首次接入跑一次 `--scan-history`）
4. 每次发版人工核对：Render Secrets 数量与 §4.1 清单一致

## 12. 备份与数据安全

| 数据 | 备份机制 | 恢复演练 |
|------|---------|---------|
| Neon Postgres | 每日自动备份 + 时间点恢复（PITR）+ 分支功能 | 季度演练一次：恢复到新分支并跑 e2e |
| COS 文件 | 对象存储自身持久性（无版本管理） | 关键文件（头像/附件）可接受丢失；AI 文档可从源文件重建 |
| Redis 队列 | 无（缓存/队列，允许丢） | 任务可重放；幂等键保证重放不重复入账 |
| 配置与密钥 | 代码库 + 平台 Secret（平台侧不导出） | 密钥丢失 = 重新生成，见 §11 |

**《隐私政策》对齐**：审计日志保留 180 天、回收站 30 天（数据字典 §6）；账号注销后按留存策略清理（cleanup 队列）。
