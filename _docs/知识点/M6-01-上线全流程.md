# M6-01 上线全流程（DNS / SSL / CDN / 迁移）

> 知识分类：M6 部署与运维 ｜ 关联里程碑：M6 ｜ 责任视角：DevOps

## 1. 这是什么
把「本地能跑的代码」变成「公网可访问的服务」的完整动作：域名解析（DNS）、HTTPS 证书（SSL）、CDN 加速、静态托管与后端托管差异、以及上线时数据库迁移的正确顺序。

## 2. 为什么值得学
- 你明确说对运维不熟悉，这一张就是你的「上线操作手册 + 学习笔记」。
- 「代码能跑」≠「服务可访问」，中间隔的就是这些基础设施知识。
- 本项目架构（Cloudflare Pages 前端 + Render 后端 + Neon 库 + 境外免备案）把这些步骤固化，照做即可。

## 3. 核心概念
- **DNS**：把 `silencewood.cn` / `app.silencewood.cn` 解析到托管方（CNAME 到 Pages / Render）。
- **SSL/TLS**：Cloudflare 自动签发 Universal SSL，免费续期；后端 Render 也自带。
- **CDN**：Cloudflare 全球缓存静态资源，国内访问更快。
- **迁移顺序**：部署新代码**前**先 `prisma migrate deploy`，否则新代码访问旧结构会报错。
- **静态 vs 服务托管**：前端是纯文件（Pages），后端是常驻进程（Render），两者部署机制不同。

## 4. 在本项目如何落地
1. 域名 NS 转到 Cloudflare；加 CNAME 指向 Pages 与 Render。
2. Cloudflare 自动 HTTPS；后端 Render 自带证书。
3. 前端 CI 构建 `dist` → 推 Pages；后端 CI 构建 → 部署 Render（先 migrate 后启动）。
4. 用 Cloudflare 把 `/api` 反代到 Render（可选，免 CORS、隐藏后端）。

## 5. 关键操作步骤（伪清单）
```
1. Cloudflare: 添加站点 → 改 NS → 等生效
2. DNS: app → CNAME → <pages>.pages.dev ; api → CNAME → <render>.onrender.com
3. SSL: 全自动（橙色云图标开代理）
4. 部署: 见 M6-02 CI/CD
5. 上线: Render 启动命令 `prisma migrate deploy && node dist/main.js`
```

## 6. 常见坑
- 忘了先 migrate 就起服务 → 新字段不存在，启动或接口报错。
- DNS 缓存（TTL）导致改了解析很久不生效 → 改之前调低 TTL。
- 混合用 A 记录与 CNAME → 混乱；统一用 CNAME 到托管方。
- 静态资源 404 → 前端 base path / 路由 history 模式没配 fallback。

## 7. 验收 / 自测清单
