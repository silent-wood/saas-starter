# C-02 安全基线（CORS / 限流 / 密钥管理）

> 知识分类：横切（贯穿全程）｜ 关联里程碑：全程 ｜ 责任视角：后端 / 安全

## 1. 这是什么
任何对外服务都该有的**基础安全配置**：跨域规则（CORS）、接口限流（防刷/防滥用）、密钥管理（不泄露）。这是安全的第一道防线。

## 2. 为什么值得学
- 这些是最常见、最该默认开启的安全项，面试与上线 checklist 都绕不开。
- 你作为前端，理解 CORS 原理能彻底搞懂「为什么本地调接口跨域报错」；限流能防盗刷。
- 密钥管理（呼应 M1-03）是安全底线中的底线。

## 3. 核心概念
- **CORS**：浏览器跨域策略；后端用白名单（仅放行你的前端域名）而非 `*` 通配。本项目前后端不同域（Pages vs Render），必须配。
- **限流（Throttler）**：单位时间限制请求次数，防暴力破解 / 爬虫 / 资损刷接口（如刷 AI 次数）。
- **密钥管理**：密钥只在平台 Secrets，绝不进代码/前端包（见 M1-03）。

## 4. 在本项目如何落地
- NestJS `CorsModule`：白名单 `['https://app.silencewood.cn']`，带凭据。
- `ThrottlerGuard`：全局限流（如 100 次/分）+ 登录接口更严格（防爆破）。
- 全部密钥经 `.env.example` 登记、平台 Secrets 注入；仓库无明文。

## 5. 关键代码示例
```ts
// CORS 白名单（伪代码）
app.enableCors({ origin: ['https://app.silencewood.cn'], credentials: true });
// 限流（伪代码）
@UseGuards(ThrottlerGuard)
@Throttle({ default: { limit: 100, ttl: 60000 } })
```

## 6. 常见坑
- 开发图省事设 `origin: '*'` 还带 credentials → 控制台报错且不安全；上线必须收紧白名单。
- 限流太松（如不限）被刷爆；太紧正常用户被拦 → 按接口分级。
- 密钥进前端包（VITE_ 变量）→ 任何人可看；前端只放公开的后端 URL。
- 限流键用 IP 但前面有 CDN/代理 → 拿到的是代理 IP，需读 `X-Forwarded-For`。

## 7. 验收 / 自测清单
- [ ] 非白名单域名调接口被 CORS 拒绝
- [ ] 高频请求触发限流（429）
- [ ] 登录接口有更严限流
- [ ] 仓库与前端包无明文密钥
