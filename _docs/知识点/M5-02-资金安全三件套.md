# M5-02 资金安全三件套（幂等 / 对账 / 资损告警）

> 知识分类：M5 订阅资金域 ｜ 关联里程碑：M5 ｜ 责任视角：后端 / 资金安全

## 1. 这是什么
即使本项目**不接真实支付网关**（v1.1 用 MockPaymentGateway），资金安全的三件套仍按真实标准完整实现——因为这是普通前端作品里**几乎见不到、却最能体现工程严谨度**的内容：
1. **幂等（Idempotency）**：同一笔订阅请求重复提交，绝不重复入账。
2. **对账（Reconciliation）**：模拟渠道流水 vs 系统账务，日终核对差异。
3. **资损告警（Loss Alert）**：检测重复入账 / 负金额 / 状态异常回跳，即时告警。

## 2. 为什么值得学
- 资金无小事：生产环境一笔重复扣款就是客诉+事故。这三件套是支付系统的底线设计。
- 设计方法与真实支付系统**同构**，你用模拟环境就能学到生产级思维，作品集差异化极强。
- 体现「不接真实网关，但能力按真实标准写全」的工程态度（呼应需求变更）。

## 3. 核心概念
- **幂等键**：请求携带唯一键（如 `tenantId:plan:period`），首次处理写「已处理」缓存/表，重复直接返回原结果。
- **对账**：每日汇总「渠道侧交易」与「我方账单」，差异（金额不符/单边账）生成差异表待人工处理。
- **资损模式**：重复入账、负金额、状态非法回跳、金额溢出——每种都有检测规则并触发告警。

## 4. 在本项目如何落地
- 订阅入口：`POST /billing/subscribe` 带 `Idempotency-Key` 头；首次落 `PaymentIdempotency` 表，重复返回首次结果。
- 日终任务（BullMQ 定时）：比对 MockGateway 流水与 `Invoice` 表，差异写 `ReconcileDiff`。
- 告警：检测到任一资损模式 → 写告警 + 发通知（复用 M3 队列 + 通知中心）。

## 5. 关键代码示例
```ts
// 幂等处理（伪代码）
async subscribe(dto, idemKey: string) {
  const existing = await idemRepo.find(idemKey);
  if (existing) return existing.result;          // 重复提交，返回首结果
  const result = await this.gateway.charge(dto); // 模拟扣费
  await idemRepo.save({ key: idemKey, result }); // 落库防重
  return result;
}
```

## 6. 常见坑
- 幂等键范围过宽（全表唯一）→ 不同用户互相挡；应含租户+业务维度。
- 只在接口层幂等、worker 重试又触发 → 关键操作全局幂等。
- 对账只看金额不看状态 → 漏掉「已退款但仍显示已付」。
- 告警只打日志无人看 → 必须接通知中心/邮件（本项目复用消息通知）。
