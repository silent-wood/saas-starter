# C-01 测试策略（Vitest / Supertest / 越权用例）

> 知识分类：横切（贯穿全程）｜ 关联里程碑：全程 ｜ 责任视角：QA / 全栈

## 1. 这是什么
为项目建立**分层测试**：单元测试（Vitest）验函数逻辑，接口测试（Supertest）验 API 行为，其中**跨租户越权用例**是多租户系统的安全回归重点。

## 2. 为什么值得学
- 测试不是「额外负担」，而是你敢重构、敢上线的底气。
- 多租户系统最大的安全回归就是「越权」——租户 A 看到了 B 的数据。这类用例必须写进测试。
- 理解测试金字塔（单测多、e2e 少），是从「手写验证」到「工程化验证」的跃迁。

## 3. 核心概念
- **单元测试（Vitest）**：测纯函数 / service 方法，快、多、隔离。
- **接口测试（Supertest）**：起 NestJS 应用，发 HTTP 请求断言响应，覆盖认证/权限/业务。
- **越权用例**：用租户 A 的令牌去访问/修改租户 B 的资源，断言 403/404。
- **测试数据库**：用独立测试库（或 transaction 回滚），不污染真实数据。

## 4. 在本项目如何落地
- `apps/api` 配 Vitest + Supertest；service 层单测，Controller 层接口测。
- 必写用例：登录签发、RBAC 拒绝、tenant_id 隔离（跨租户访问失败）、订阅状态机合法/非法迁移、幂等键去重。
- CI 里 `pnpm test` 作为质量门禁（见 M6-02）。

## 5. 关键代码示例
```ts
// 越权用例（伪代码）
it('租户B不能访问租户A的资源', async () => {
  const res = await request(app)
    .get(`/resources/${aResourceId}`)
    .set('Authorization', `Bearer ${tenantBToken}`);
  expect(res.status).toBe(403); // 或 404，查不到
});
```

## 6. 常见坑
- 只测「正常路径」不测「异常/越权」→ 安全回归裸奔。
- 测试依赖真实外部服务（DB/Redis）→ 不稳定；用内存或 mock。
- 测试数据没清理 → 越跑越脏；用事务回滚或 before/after 钩子。
- 测试覆盖率为 0 还敢上线 → 至少核心鉴权/隔离/资金路径要有测试。

## 7. 验收 / 自测清单
- [ ] 越权用例存在且通过（跨租户访问被拒）
- [ ] RBAC 接口级拒绝用例通过
- [ ] 幂等 / 状态机关键分支有测试
- [ ] CI 测试不过则阻断部署

## 8. 延伸学习
- 测试金字塔 / 测试替身（mock/stub/spy）
- Supertest + NestJS 测试官方指南
- 覆盖率与 mutation testing
