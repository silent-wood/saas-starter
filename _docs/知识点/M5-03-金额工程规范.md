# M5-03 金额工程规范（Decimal / 分）

> 知识分类：M5 订阅资金域 ｜ 关联里程碑：M5 ｜ 责任视角：后端 / 资金安全

## 1. 这是什么
**绝不用浮点数存金额**。金额一律以「分（整数）」存储，或用语义化十进制类型（Decimal / 定点数）做计算。这是避免 `0.1 + 0.2 ≠ 0.3` 这种资损事故的工程铁律。

## 2. 为什么值得学
- `0.1 + 0.2 = 0.30000000000000004` 是 IEEE 754 浮点的固有缺陷；用在钱上就是**真实的资损 bug**。
- 掌握金额规范，是你从「写页面」到「写金融级严谨后端」的标志性一跃。
- 本项目虽是模拟支付，但规范按真实标准执行，体现工程态度。

## 3. 核心概念
- **整数分存储**：所有金额以最小货币单位（分）整数存，展示时 `/100`。
- **Decimal 类型**：数据库用 `Decimal`/numeric，语言用 `decimal.js` / `Prisma Decimal`，杜绝浮点。
- **计算顺序**：先乘后除、保留精度、四舍五入规则统一。
- **展示与存储分离**：存储整数分，前端格式化显示「¥12.34」。

## 4. 在本项目如何落地
- Prisma：`amount Decimal @db.Decimal(12,2)` 或存 `amountCents Int`。
- 计算一律走 `decimal.js`，`+ - *` 不用 JS 原生 `number`。
- 账单/发票金额、套餐定价统一以分计；前端用格式化函数展示。

## 5. 关键代码示例
```ts
// 错误：浮点
const wrong = 0.1 + 0.2;             // 0.30000000000000004
// 正确：整数分
const a = 10, b = 20;                // 分
const total = a + b;                 // 30 分 = ¥0.30
// 或 decimal.js
import Decimal from 'decimal.js';
const d = new Decimal('0.1').plus('0.2'); // '0.3' 精确
```

## 6. 常见坑
- 前端用 `parseFloat` 参与金额运算 → 又回到浮点陷阱；金额展示用 `Intl.NumberFormat` 而非手算。
- 数据库用 `Float` 列 → 精度丢失；必须用 Decimal/numeric。
- 汇率/折扣计算先除后乘 → 精度误差累积；保持高精度中间值。
- 分与元混用没标注 → 对账时单位错乱（务必字段命名 `amountCents`/`amount` 区分）。

## 7. 验收 / 自测清单

- [ ] 所有金额计算走 Decimal，无裸 number 运算
