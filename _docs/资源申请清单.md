## 阶段一：今天完成（硬阻塞，不做完 M2 无法开工）

### □ 1. Neon（数据库 · 阻塞 M2）

- 申请：https://console.neon.tech/signup
- ⚠️ **控制台建项目入口已变更**：新建 Project 页面会提示「要创建新项目，请使用 Vercel 中的 Neon Postgres 集成」。**这不影响申请本身**，用 CLI 建项目即可绕过（详见下方）
- **创建 Project（推荐 CLI 路径）**：
  ```bash
  npm i -g neon          # 包名已改 neon，neonctl 是别名
  neon login             # 打开浏览器完成授权（仅限 Neon 直接注册的账号）
  neon projects create --name saas-starter --region-id aws-ap-southeast-1 --pg-version 17
  ```
  - 若账号是 Vercel 托管的（组织名形如 `Vercel: <team>`），`neon login` 浏览器授权不可用 → 控制台 → Account Settings → API Keys → Create → `export NEON_API_KEY=...` 后再执行建项目命令（个人 API key 跨组织通用）
  - region 可选：`aws-us-east-1` / `aws-us-east-2` / `aws-us-west-2` / `aws-eu-central-1` / `aws-eu-west-2` / `aws-ap-southeast-1`（新加坡）/ `aws-ap-southeast-2` / `aws-sa-east-1`（**Tokyo 已下线；Azure 三区已弃用不得新建**）
  - **region 建后不可更改**，换区 = 新建项目 + 迁移数据，控制台默认值 Ohio 需手动改成 Singapore
- **若用控制台建项目**（即出现「请使用 Vercel 集成」提示的那一屏）：Region 选 Singapore；**Postgres database 开**（展开后版本选 17）；**Object storage / Functions / AI gateway / Realtime / Better Auth 全部关**（本项目文件走 R2、后端走 Render、认证自研、LLM 走 OpenAI Key、实时用自建 SSE；AI gateway 更是 Free 档不可用）。详见部署运维手册 §6.3.0.1
- 拿两条连接串：项目 Dashboard → **Connect** 按钮 → 弹窗里有个 **Connection pooling 开关（默认已开）**，开 = 显示池化串、关 = 显示直连串（开关只切换显示，池化端点始终存在）：
  - `DATABASE_URL`（池化，host 带 `-pooler`）→ 运行时用
  - `DIRECT_DATABASE_URL`（直连）→ Prisma Migrate 用
  - 连接串自带 `?sslmode=require&channel_binding=require`，**不要手动删这两个参数**
- 在 SQL Editor 执行：`CREATE EXTENSION IF NOT EXISTS vector;`
- 验证：`SELECT extname, extversion FROM pg_extension WHERE extname = 'vector';`
- 免费档：**1GB 存储/项目**、100 CU-hour/月、100 项目/账户、**空闲 5 分钟自动挂起（不可关闭）**

### □ 2. Resend（邮件 · 阻塞 M2）

- 申请：https://resend.com/signup
- API Keys → Create API Key → 复制 `re_xxx`（**只显示一次**）
- Domains → Add Domain → `silencewood.cn` → 把提示的 DNS 记录加到 Cloudflare
- 免费档：3000 封/月，**100 封/天（日限硬顶）**
- ⚠️ 生产必须走 HTTPS API，**不要用 SMTP**（Render 免费档封了 25/465/587）

### □ 3. 密钥生成 + GitHub Secrets

- 生成 JWT_SECRET：`openssl rand -base64 48`
- 仓库 Secrets 页面：https://github.com/silent-wood/saas-starter/settings/secrets/actions
- 至少先加：`DATABASE_URL` / `DIRECT_DATABASE_URL` / `JWT_SECRET` / `MAIL_API_KEY` / `MAIL_FROM`
- 完整清单见部署运维手册 §4.1（后端 24 项 + 前端 1 项）

## 阶段二：M3 开工前（文件与队列）

### □ 4. Upstash Redis

- 申请：https://console.upstash.com/（注册免绑卡）
- 产品卡片选 **Redis**（⚠️ 不是 QStash——那是 HTTP 消息服务，说不了 Redis 协议，BullMQ 用不了）
- **Create Database**：名称 `saas-starter`；Primary Region 选 **AWS Singapore（ap-southeast-1）**，与 Neon 同区；Type 选 **Regional**（不是 Global）；**Eviction 关**（队列/缓存数据被逐出 = 任务丢失，BullMQ 场景必须关）；TLS 默认开
- Details 页复制 **`rediss://default:<password>@<host>:6379`**（TCP 协议连接串，不是 REST URL/Token——ioredis/BullMQ 走 TCP）→ 这就是 `REDIS_URL`
- 免费档（2026-10 官方定价页）：**256MB、50 万命令/月、1 个免费库**（别建测试库，就这一个名额）→ BullMQ 需 `maxRetriesPerRequest: null`
- 命令消耗提醒：BullMQ 空转轮询也计命令数，演示期日常用量远够；免费档超限是限流不是扣费（无绑卡）

### □ 5. Cloudflare R2（文件存储）

- 申请：https://dash.cloudflare.com/sign-up
- ⚠️ **激活 R2 需先绑卡**（Billing → Payment Method，银联/Visa/MC 均可；免费额度内不扣费，仅超额按量计费）→ R2 页面点激活订阅
- 入口（2026 侧栏改版后）：左栏 **Build → Storage & databases → R2 Object Storage → Overview**（不再是一级菜单）
- **Create bucket** → 名称 `saas-starter`（小写字母/数字/连字符）→ Location 选 **APAC**（靠近 Neon 新加坡）→ Standard
- Token：R2 Overview 页拉到底 **Account Details → API Tokens → Manage** → Create Account API Token → 权限 **Object Read & Write** → Apply to specific buckets
- 复制 `Account ID` / `Access Key ID` / `Secret Access Key` / S3 endpoint（**只显示一次，立即存入 Secrets**）
- 公开访问（演示级）：bucket → Settings → 开 **Public Development URL**（`pub-xxx.r2.dev` 立即可用）；**自定义域名要等域名 NS 迁到 Cloudflare 后才能绑**（当前 NS 在 DNSPod）
- 免费档：10GB 存储 + 100 万次写/月

## 阶段四：M6 开工前（部署上线）

### □ 7. Render（后端运行时）

- 申请：https://dashboard.render.com/signup
- New → Web Service → Connect repo `silent-wood/saas-starter`
- 免费档限制（必须知情）：512MB/0.1CPU、15 分钟休眠、冷启动约 1 分钟、**SMTP 端口封锁**、本地文件系统临时
- 演示建议：切常驻实例（约 ¥70–140/月，需求文档预算 ¥100/月内）

### □ 8. Cloudflare Pages + DNS

- 申请：https://dash.cloudflare.com/sign-up（与 R2 同一账号）
- 添加站点 `silencewood.cn` → 按提示把域名 NS 改到 Cloudflare 给出的两条 Nameserver（在域名注册商后台改；**当前 NS 在腾讯云 DNSPod，实测 harlan/vole.dnspod.net**）
- **切 NS 前先把 DNSPod 现有记录（其他仓库在用的）在 Cloudflare 逐条重建**——迁移是搬家不是清空，Add Site 自动扫描会漏，以 DNSPod 记录列表为准核对；其他仓库的 GitHub Pages / Vercel 记录用**灰云（DNS only）**，仅本项目 app/api 用橙云
- **改之前把已有记录的 TTL 降到 60 秒**（生效后再调回 3600）
- Pages：Workers & Pages → Create → Pages → Connect to Git → 分支 main
  - Build command：`pnpm --filter web build`
  - Output dir：`apps/web/dist`
  - Root directory：**留空**（填 `apps/web` 会找不到 workspace）
  - 环境变量：`VITE_API_BASE_URL` = `https://api.silencewood.cn/api/v1`
- DNS 记录（**橙云代理必须开**）：
  - `app` → CNAME → `<project>.pages.dev`
  - `api` → CNAME → `<service>.onrender.com`
- SSL/TLS → Universal SSL（自动）→ Edge Certificates → Always Use HTTPS: On

## 申请期常见问题速查

| 现象 | 原因 | 处理 |
|------|------|------|
| Neon 控制台提示「请使用 Vercel 中的 Neon Postgres 集成」 | 2026-10 起控制台不再作为默认建项目入口 | 用 CLI 建：`neon projects create --name saas-starter --region-id aws-ap-southeast-1` |
| `neon auth` 提示无法浏览器授权 | 账号是 Vercel 托管注册的 | 控制台建 API Key → `export NEON_API_KEY=...` → 再执行建项目命令（新 CLI 里命令叫 `neon login`） |
| 点 Create 报 `action restricted; "organization is managed by Vercel"` | 当前组织由 Vercel Marketplace 集成创建，禁止在其中建项目 | 左上角组织下拉切到个人组织再建；或 CLI 建项目命令加 `--org-id`（`neon orgs list` 查）——详见部署手册 §6.3.0.2 |
| Neon 报连接超时 | 用了直连地址连 serverless 运行时 | 运行时换池化地址（`-pooler`） |
| Prisma 迁移失败 | 用了池化地址做迁移 | 迁移改用 `DIRECT_DATABASE_URL` |
| `CREATE EXTENSION vector` 报已存在 | 扩展已装 | 无需处理，忽略即可 |
| Resend 只能发给自己 | 域名未验证 | 补 DNS 记录后等验证通过 |
| OpenAI 报余额不足 | 预付费未充值 | Billing 充值 |
| R2 密钥找不到 | Token 只显示一次 | 撤销旧的重新生成 |
| 上线后邮件超时 | 免费档封了 SMTP 端口 | 改用 HTTPS API（不是代码问题） |
| 改 DNS 后不生效 | DNS 缓存 | 调低 TTL 等生效，必要时清本地 DNS 缓存 |
| Pages 构建找不到 pnpm | Node 版本不对 | 加环境变量 `NODE_VERSION=22` |
