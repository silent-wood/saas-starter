## 1. 项目概述与目标

### 1.1 背景

本需求文档定义一套**通用型多租户中后台 SaaS 全栈脚手架（SaaS Starter）**。目标不是交付某个具体业务产品，而是提供一个可复用、可演示、覆盖全栈关键能力的工程基座，用作技术作品集与后续真实业务落地的起点。

### 1.2 目标

- 覆盖全栈八大验证点：前端工程化、后端架构、数据建模、认证授权、AI 集成、异步任务、文件存储、部署运维。
- 内置一个**示例业务域**（如「团队工作区 / 示例资源」），仅用于演示多租户能力，不绑定真实业务。
- 以最小可行资源（个人 / 演示级）跑通端到端链路：注册 → 创建租户 → 登录 → 业务 CRUD → AI 辅助 → 订阅模拟 → 通知。
- 文档与代码对**前端背景的开发者友好**：对后端 / 运维概念给出足够说明与上手指引（见附录术语速查）。

### 1.3 非目标（v1 明确不做）

- **对接真实支付渠道**（微信/支付宝/Stripe）。注意：订阅资金链路的需求内容**按真实场景完整设计**（见 5.3），仅以模拟网关实现；非目标只是「不对接外部渠道」。
- 真实短信通道（仅做接口预留与模拟）。
- **WebSocket 全双工实时协作**。目标态需求已完整定义（见 5.5），v1 以 SSE 单向推送降级实现，完整实现列入后续版本池。
- 多区域、高可用、水平扩容。
- 复杂数据分析 / BI 报表。
- 开放平台能力（Webhook / API Key / 开放 API）——后续版本 v2。

## 4. 系统总体架构

分层（与架构图一致，仅前端托管框改为 Cloudflare Pages）：

- **客户端层**：Web Admin（Cloudflare Pages 静态）— Vite SPA
- **接入层**：Cloudflare 边缘（CDN / SSL）；可选 `/api` 反代到后端实现同源
- **应用层**：NestJS API（Render/Railway）— BFF + 领域服务
- **服务层**：认证租户、业务域、AI 服务、支付模拟、消息通知、任务调度（BullMQ）
- **数据层**：Postgres（Neon）+ pgvector、Upstash Redis、对象存储（R2）
- **运维层**：GitHub Actions CI/CD、平台自带日志 / 监控、Neon 自动备份

**数据流**  
浏览器 → Cloudflare CDN →（CORS 或反代）→ NestJS → Prisma → Postgres；  
异步任务经 BullMQ → Upstash → Worker 消费；  
AI 经 SDK → LLM API + pgvector 向量检索。

## 5. 功能模块详述

### 5.1 基线能力

- **多租户**：注册即创建租户；登录后所有数据按 `tenant_id` 隔离。
- **认证与 RBAC**：邮箱 + 密码注册 / 登录（JWT）；角色 `owner / admin / member`；基于角色的接口与按钮级权限。
- **成员生命周期**：待激活（受邀未注册）→ 激活 → 正常；支持**禁用**（保留数据、禁止登录本租户）、**移除**（二次确认）、**owner 转让**（转让后原 owner 降为 admin，需二次确认）。
- **业务域 CRUD**：示例「工作区 / 资源」实体的增删改查、分页、过滤。
- **软删除 / 回收站**：资源删除进入回收站（逻辑删除），30 天内可恢复，到期物理删除；回收站仅 owner / admin 可管理。
- **文件存储**：头像 / 附件上传到 R2，返回可访问 URL，元数据入 DB。演示环境单文件 ≤ 10MB（见 §3 资源清单 / 用户手册 FAQ）。
  - **可选增强（大文件分片上传，Multipart Upload）**：当需支持 > 10MB（生产常设 100MB~~5GB 上限）文件时，将单 PUT 直传升级为 S3/R2 原生分片上传——后端 `createMultipartUpload` 签发 `uploadId` 与分片级预签名 URL，前端切片（≥5MB/片，末片可更小）并发直传并收集 ETag，完成后 `completeMultipartUpload` 合并；失败/放弃时 `abortMultipartUpload` 清理半成品。可选叠加**断点续传**（前端存 `uploadId`+分片状态于 IndexedDB，刷新后 `listParts` 补传）、**进度与并发**（限 3~~5 路）、**秒传去重**（文件 hash 命中直接引用）。设计细节见 `知识点/M3-01` 第 9 节。该增强不计入 v1 必交付，列为可选实现，按需开启。
- **审计日志**：记录敏感操作（登录、权限/成员变更、数据删除、订阅变更、配额调整）；字段：操作人、时间、IP、动作、对象、结果；仅 owner / admin 可查看与筛选；保留 180 天（与《隐私政策》留存策略一致）。
- **租户设置**：租户名称、Logo、品牌主色配置（演示品牌化能力）。
- **用户中心**：资料、改密、租户切换。

### 5.2 AI 智能模块

- **智能问答 / 摘要（RAG）**：将租户内文档 / 数据切分 → 向量化（pgvector）→ 检索 → LLM 生成。
- 接口：`POST /ai/ask`，流式返回（SSE）。
- 成本与降级：演示级用小额 LLM API；可降级为「规则模板」模式避免超额。

### 5.3 订阅与支付（模拟网关 · 需求内容完整版）

**设计原则**：不对接真实支付渠道，但订阅资金链路的需求内容**按真实资金场景完整设计**。实现层通过 `MockPaymentGateway`（策略模式）提供与真实网关一致的接口契约（下单/回调/查询/退款），后续替换真实渠道时业务层零改动。

**套餐模型**

| 套餐   | 席位上限 | AI 用量额度（自然月） | 存储配额  | 月价（演示标价）      |
| ---- | ---- | ------------ | ----- | ------------- |
| Free | 3    | 20 次问答       | 100MB | ¥0            |
| Pro  | 20   | 500 次问答      | 5GB   | ¥29（模拟，不真实扣款） |

- 新租户默认 Free；可发起 **14 天 Pro 试用**，每租户限一次。

**订阅状态机**

```
none → trialing → active → past_due → canceled / expired
```

| 状态       | 触发                      | 规则                                        |
| -------- | ----------------------- | ----------------------------------------- |
| trialing | 发起试用                    | 14 天，权益同 Pro；到期未模拟支付 → expired（回 Free 权益） |
| active   | 模拟支付成功                  | 权益即时生效，写账单                                |
| past_due | 续费模拟失败                  | **3 天宽限期**，权益保留；宽限期内并发续费重试**仅扣一次**（幂等约束）  |
| canceled | 期末取消 / 立即取消（owner 二次确认） | 期末取消当期权益保留至期末；立即取消即时降级                    |
| expired  | 试用到期未转化 / 订阅到期未续费       | 回 Free 权益，数据保留                            |

- 状态**单向流转，禁止回跳**；每次迁移写订阅事件表（含幂等键、触发来源、时间）。
- **模拟退款**：Pro 订阅期内可全额退款（二次确认），即时降级 Free，账单标记已退款。

**资金底线三件套（模拟环境同样执行，作为能力展示）**

| 项    | 实现要求                                                         |
| ---- | ------------------------------------------------------------ |
| 幂等   | 订阅/续费/退款请求携带幂等键（租户 + 套餐 + 周期 + 渠道流水号），重复提交 / 网络重试**不重复入账**   |
| 对账   | 日终定时任务比对模拟渠道流水 vs 系统账务记录，差异写入对账差异表（状态：待处理 / 已解释）；演示环境差异可人工标记 |
| 资损监控 | 异常检测四类：重复入账、负金额、状态回跳、对账差异 → 触发告警（站内通知 + 邮件）；演示环境落告警日志        |

**金额规范**：一律以**分（Decimal）**&#x5B58;储与计算，禁止浮点；舍入规则统一四舍五入。

**账单中心**：账单历史列表（周期、金额、状态、幂等键）、模拟发票页；权益变更（升降级/退款）即时生效并通知。

**权益联动**：席位上限、AI 额度、存储配额随套餐变化（执行规则见 5.6）；超额时给出明确升级引导，不阻断已付费权益内功能。

### 5.4 消息通知（邮件为主 + 短信模拟）

- **邮件**：注册验证、找回密码、订阅变更、资损告警，经 nodemailer / SMTP 或 Resend。
- **通知偏好**：用户可按类别（订阅 / 成员 / 系统 / 告警）开关邮件通知；**站内通知不可关闭**，安全类告警邮件不可关闭。
- **短信**：仅预留接口 + 模拟发送（日志 / 控制台），不接真实通道（真实短信需企业资质与模板审核）。
- **通知中心**：站内消息表 + 未读计数。

### 5.5 实时协作（v1 降级实现 · 目标态完整定义）

**目标态需求（完整定义，v1 只做降级实现）**：

1. **成员在线状态（presence）**：同租户成员的在线 / 离线状态实时可见；
2. **资源变更实时同步**：他人创建 / 修改 / 删除资源时，同租户在线成员即时感知；
3. **通知实时推送**：站内通知产生即推送，无需刷新。

**v1 降级实现（范围与边界）**：

- 复用 AI 模块的 **SSE 单向推送通道** + 前端轮询兜底（30s）；
- 通知类（3）完整实时；变更同步（2）降级为「数据已变更」提示条 + 刷新引导，**不做合并编辑**；presence（1）降级为「最近活跃时间」展示。

**v2 完整实现（后续版本池，含触发条件）**：

- Socket.IO 全双工 + presence 心跳 + 乐观更新与冲突提示；
- 触发条件：v1 上线后验证到真实协作诉求（多人同时编辑频次）再启动，避免为演示过度投入。

### 5.6 用量与配额

- **用量看板**：席位、存储、AI 问答次数（当月）的当前值 / 上限 / 用量百分比，订阅页与工作台可见。
- **配额执行规则**：

| 配额      | 超额行为                    |
| ------- | ----------------------- |
| AI 问答次数 | 当月超额后停用 AI 功能至次月，给出升级引导 |
| 存储配额    | 上传拦截，提示清理或升级            |
| 席位上限    | 邀请拦截，提示升级               |

- **统计口径**：AI 用量 = 当月（自然月，UTC）问答接口**成功**次数；存储 = 已上传文件字节数总和（含软删除未到期文件）。

## 6. 多租户数据隔离设计

两种方案对比：

- **A. 行级隔离（共享库 + tenant_id）**：所有表加 `tenant_id`，查询强制带租户过滤（NestJS 用 Request-scoped 服务 / 全局拦截器注入当前租户）。
  - 优点：简单、成本低、演示友好、迁移容易。
  - 缺点：隔离靠代码纪律，漏写过滤有越权风险（靠测试兜底）。
- **B. Schema 隔离（每租户独立 schema）**：租户数据物理隔离。
  - 优点：强隔离、单租户备份 / 恢复容易。
  - 缺点：连接与迁移管理复杂、成本随租户增长。

**推荐 A（行级隔离）** 用于 v1，配合全局租户守卫 + 自动化越权测试。文档给出 Prisma 模型示例与守卫实现要点，并标注 B 方案的迁移路径。

## 7. 安全基线

- **传输安全**：全站 HTTPS（Cloudflare 自动 Universal SSL）。
- **认证**：JWT（短期 access + 刷新机制），密码 bcrypt 哈希，登录失败限流。
- **授权**：RBAC + 租户守卫，所有查询强制带 `tenant_id`。
- **注入 / XSS**：Prisma 参数化查询防 SQL 注入；前端输出编码；配置 CSP 响应头。
- **限流**：API 级限流（@nestjs/throttler）。
- **密钥管理**：密钥仅存平台 Secrets / 环境变量，绝不入仓；`.env.example` 仅列变量名。
- **CORS**：白名单仅含你的域名（`app.silencewood.cn` 等）。


## 9. 合规

- 必填：**隐私政策**与**使用条款**页面。
- 《个人信息保护法》要点：最小收集、明示同意、数据可删除（提供账号注销 / 数据导出）。
- 日志不记录明文密码 / 令牌；敏感操作留审计记录。

### 10.3 风险与待办

- **范围蔓延（新增，等级：高）**：v1.1 范围已扩约 +50%（估算），后续版本池已冻结；**新增需求一律走变更评估表**，非核心诉求默认进版本池。

## 附录：术语速查（面向前端同学）

| 术语               | 一句话解释                                                            |
| ---------------- | ---------------------------------------------------------------- |
| Monorepo         | 前端 / 后端 / 共享代码放在**一个仓库**里，用工具（pnpm workspace + Turborepo）统一管理与构建 |
| Prisma           | Node 的 ORM（对象关系映射）：用 TypeScript 定义数据表结构，自动生成 SQL 与类型安全的查询代码      |
| PostgreSQL       | 开源关系型数据库，存业务数据；Neon/Supabase 提供云端托管版本                            |
| pgvector         | Postgres 的扩展，能存「向量」，用于 AI 语义检索（RAG）                              |
| NestJS           | 企业级 Node 后端框架，模块化、依赖注入，便于展示架构素养                                  |
| JWT              | 登录后发给前端的令牌，后端用它识别「你是谁、属于哪个租户」                                    |
| RBAC             | 基于角色的访问控制：不同角色（owner/admin/member）能访问不同接口                        |
| BullMQ + Redis   | 异步任务队列：把「发邮件 / AI 处理」等慢任务丢到后台，不阻塞接口                              |
| Upstash          | 托管的 serverless Redis，按量计费、有免费档，免运维                               |
| CORS             | 浏览器跨域限制；需后端白名单允许你的前端域名，否则请求被拦                                    |
| CI/CD            | 代码推送后自动「检查 → 测试 → 构建 → 部署」的流水线（GitHub Actions）                   |
| Cloudflare Pages | 静态站点托管：把前端打包后的文件放到全球 CDN，自动 HTTPS，免备案（境外）                        |
| Render / Railway | 托管 Node 服务的云平台，连 GitHub 自动部署，免备案（境外）                             |
| ICP 备案           | 国内服务器必须做的域名实名备案；用境外服务则可跳过                                        |
